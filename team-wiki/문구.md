# 문구와 말투 (copy)

> **영역 요약:** 알림과 AI 설명의 문장 규칙, 함께 쓰는 말
> **관련 문서:** 용어 정리, 스펙: 바뀐 기준 찾기 "AI가 쓰는 문장"
> **DRI:** 부건님

### copy.explain.plain-words
- 제목: 변경 설명에는 개발 용어 대신 쉬운 말을 쓴다
- 값: AI가 쓰는 변경 설명은 개발 용어를 꼭 필요할 때만 쓰고, 처음 나오면 괄호로 풀어 쓴다
- 이유: 디자이너와 다른 팀 사람도 1분 안에 판단해야 한다
- 적용 범위: 코드: packages/detect/src/prompt/** / 화면: 터미널 알림, 앱 알림
- 근거: 스펙: 바뀐 기준 찾기 "AI가 쓰는 문장"
- 항상 적용: 예
- 상태: 사용
- 버전: 1

### copy.explain.before-after
- 제목: 변경 설명은 이전 값과 지금 값을 한 문장씩 쓴다
- 값: 변경 설명은 이전 값과 지금 값을 같은 문장 구조로 한 문장씩 써서 차이가 보이게 한다
- 이유: 구조가 같아야 무엇이 바뀌었는지 한눈에 보인다
- 적용 범위: 코드: packages/detect/src/prompt/** / 화면: 터미널 알림
- 근거: 스펙: 바뀐 기준 찾기 "AI가 쓰는 문장"
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### copy.explain.reason-one
- 제목: 변경 이유는 왜 바꿨는지 한 문장으로 쓴다
- 값: 변경 이유는 왜 바꿨는지만 한 문장으로 쓰고, 근거에 없는 영향은 추측해 쓰지 않는다
- 이유: 추측이 들어가면 담당자가 잘못 판단한다
- 적용 범위: 코드: packages/detect/src/prompt/**
- 근거: 스펙: 바뀐 기준 찾기 "AI가 쓰는 문장"
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### copy.term.standard
- 제목: 팀 위키의 항목은 "기준"이라고 부른다
- 값: 팀 위키의 항목 하나는 기준이라고 부르고, 결정 사항·스펙·RULE이라고 부르지 않는다
- 이유: 같은 것을 여러 말로 부르면 사람과 AI 모두 헷갈린다
- 적용 범위: 문서: 용어.md / 화면: 전체
- 근거: 용어 정리 "쓰지 않는 말"
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### copy.term.related
- 제목: 답은 "관계있다/관계없다", "알았다/몰랐다"로 부른다
- 값: 담당자의 답은 관계있다/관계없다와 알았다/몰랐다로 부르고, 수락/거절이나 영향 있음/영향 없음은 쓰지 않는다
- 이유: 수락/거절은 기준을 승인하는 것처럼 들린다
- 적용 범위: 화면: 터미널 알림, 나에게 온 변경, Slack DM / 코드: packages/core/src/types/**
- 근거: 용어 정리 "제품 용어"
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### copy.term.issue
- 제목: 이 도구의 할 일 하나는 "이슈"라고 부른다
- 값: 이 도구가 갖고 있는 작업 목록의 한 건은 이슈라고 부르고 작업·태스크라고 부르지 않는다
- 이유: 화면과 알림에서 같은 말을 써야 헷갈린다
- 적용 범위: 문서: 용어.md / 화면: 전체
- 근거: 착수 안내 "이슈 목록" · Linear SIL-79
- 항상 적용: 아니오
- 상태: 사용
- 버전: 2

### copy.term.this-tool
- 제목: 서비스 이름을 정하기 전에는 "이 도구"라고 부른다
- 값: 임시 서비스 이름이 정해지기 전까지 문서와 화면에서는 이 도구라고 부르고 예전 가제는 쓰지 않는다
- 이유: 정하지 않은 이름이 화면과 코드에 퍼지면 나중에 고치기 어렵다
- 적용 범위: 문서: 전체 / 화면: 전체
- 근거: 용어 정리 "쓰지 않는 말" · PRD-02
- 항상 적용: 아니오
