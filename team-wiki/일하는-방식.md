# 일하는 방식 (work)

> **영역 요약:** 결과물에 영향을 주는 팀 규칙 (위키 기록, 브랜치, 리뷰, 배포)
> **관련 문서:** 일하는 방식, v0 도그푸딩 가이드
> **DRI:** 호윤님

### work.wiki.changelog
- 제목: 기준을 바꾸면 CHANGELOG에 한 줄 남긴다
- 값: 기준을 새로 만들거나 고치거나 폐기하면 CHANGELOG.md 맨 아래에 정해진 형식으로 한 줄을 남긴다
- 이유: 이 기록이 주 지표와 바뀐 기준 찾기 정확도 실험의 정답이 된다
- 적용 범위: 문서: CHANGELOG.md / 문서: 최상단 CLAUDE.md
- 근거: v0 도그푸딩 가이드 "CHANGELOG 한 줄"
- 항상 적용: 예
- 상태: 사용
- 버전: 2

### work.wiki.ask-before-change
- 제목: 위키와 다르게 만들게 되면 먼저 기준을 바꾸는지 묻는다
- 값: AI가 위키의 기준과 다른 결과물을 만들게 되면 만들기 전에 사람에게 팀 기준을 바꾸는 것인지 먼저 묻는다
- 이유: 묻지 않고 만들면 위키와 결과물이 조용히 달라진다
- 적용 범위: 문서: 최상단 CLAUDE.md
- 근거: v0 도그푸딩 가이드 "각자 CLAUDE.md에 넣을 규칙"
- 항상 적용: 예
- 상태: 사용
- 버전: 2

### work.wiki.figma-record
- 제목: Figma만 고친 날은 #작업 채널에 기준 변경을 남긴다
- 값: Claude Code를 거치지 않고 Figma에서 기준을 바꾸면 CHANGELOG에 직접 한 줄 남기거나 #작업 채널에 "기준 변경:"으로 시작하는 한 줄을 남긴다
- 이유: Figma 변경이 기록에서 빠지면 디자인 쪽 변경 수를 셀 수 없다
- 적용 범위: 문서: CHANGELOG.md / 화면: Figma
- 근거: v0 도그푸딩 가이드 "디자이너가 Figma만 고친 날"
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### work.decision.linear-first
- 제목: 정해진 것은 Linear에 이유와 함께 적는다
- 값: 결정은 Linear에 이유와 함께 적고 Slack에는 링크만 남기며, DM으로 정하지 않는다
- 이유: 결정의 이유가 한곳에 남아야 나중에 기준의 근거로 쓸 수 있다
- 적용 범위: 문서: Linear 이슈와 문서
- 근거: 일하는 방식 "도구는 이렇게 나눠 써요"
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### work.review.within-4h
- 제목: 리뷰 요청은 4시간 안에 본다
- 값: 코드 리뷰 요청은 4시간 안에 보고, 못 보면 못 본다고 남긴다
- 이유: 매일 저녁 세 기능을 합쳐 봐야 해서 리뷰가 늦으면 통합이 밀린다
- 적용 범위: 코드: 전체 저장소

- 항상 적용: 아니오

- 버전: 2

### work.release.staged
- 제목: 배포는 2명, 사일로 전원, 다른 팀 순서로 넓힌다
- 값: 새 기능은 팀원 2명에게 먼저 배포하고, 문제가 없으면 사일로 전원, 그다음 다른 팀 순서로 넓힌다
- 이유: 문제를 작은 범위에서 먼저 찾아야 다른 팀의 신뢰를 잃지 않는다
- 적용 범위: 문서: 설치 안내 / 코드: .github/workflows/release.yml
- 근거: 일하는 방식 원칙 4 · Linear 마일스톤
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### work.data.other-team-consent
- 제목: 다른 팀 데이터는 동의를 받고 끝나면 지운다
- 값: 다른 팀 저장소에 설치하기 전에 코드 변경이 Claude API로 보내진다는 동의를 받고, 사용이 끝나면 그 팀의 데이터를 지운다
- 이유: 다른 팀의 코드와 답을 동의 없이 다루면 안 된다
- 적용 범위: 문서: 설치 안내 / 코드: packages/core/src/db/**
- 근거: 아직 정하지 않은 것 · Linear 검증과 발표 프로젝트 · SIL-99 (10/15 호윤님 결정)
- 항상 적용: 아니오
- 상태: 사용
- 버전: 2

### work.review.self-merge
- 제목: 리뷰 승인 없이 본인이 머지하고 CI로 검사한다
- 값: PR은 리뷰 승인 없이 작성자 본인이 머지하며, 코드 검사는 CI로 한다
- 이유: 리뷰 승인을 기다리지 않고 CI 검사로 대신하기로 바뀌었다
- 적용 범위: 코드: 전체 저장소
- 근거: Linear SIL-60 댓글 (10/9) · SIL-61
- 항상 적용: 아니오
- 상태: 사용
