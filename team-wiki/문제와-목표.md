# 문제와 목표 (goal)

> **영역 요약:** 어떤 문제를 누구를 위해 풀고, 무엇으로 성공을 재는지
> **관련 문서:** PRD-01, 사일로 OKR과 지표, MVP 범위
> **DRI:** 호윤님

### goal.problem.rework
- 제목: 이 도구는 바뀐 기준을 몰라서 생기는 재작업을 줄인다
- 값: 이 도구의 목적은 각자 AI와 일하는 팀에서 바뀐 기준을 모르고 예전 기준으로 일하다 생기는 재작업을 줄이는 것이다
- 이유: 기능을 고를 때 이 목적에 도움이 되는지로 판단한다
- 적용 범위: 문서: 발표 자료 / 화면: 지표
- 근거: PRD-01 "한 줄 요약"
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### goal.user.first-team
- 제목: 첫 사용자는 Claude Code로 일하는 여러 직군 팀이다
- 값: MVP의 첫 사용자는 개발자와 디자이너가 각자 Claude Code로 작업하는 팀이다
- 이유: 알림을 Claude Code 세션 시작에 띄우는 설계가 이 사용자를 전제로 한다
- 적용 범위: 코드: packages/cli/src/brief/** / 문서: 설치 안내
- 근거: PRD-01 "누가 쓰나요" · MVP 범위
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### goal.scope.metric-first
- 제목: 주 지표를 모으는 데 필요 없는 기능은 뒤로 미룬다
- 값: 10/15까지 실제 사용에서 "몰랐다" 답을 모으는 데 필요하지 않은 기능은 이번 범위에서 만들지 않는다
- 이유: 1.5주 안에 가설을 검증하려면 범위를 좁혀야 한다
- 적용 범위: 문서: MVP 범위
- 근거: MVP 범위 "기준은 하나예요" · 일하는 방식 원칙 7
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### goal.scope.one-team
- 제목: MVP는 팀 하나와 저장소 하나만 지원한다
- 값: 이번 범위에서는 팀 하나가 저장소 하나에 붙여 쓰는 경우만 지원하고, 여러 팀과 여러 프로젝트는 지원하지 않는다
- 이유: 여러 팀을 지원하면 권한과 데이터 분리가 필요해 일정 안에 끝낼 수 없다
- 적용 범위: 코드: packages/core/src/** / 문서: MVP 범위
- 근거: MVP 범위 "이번에 하지 않을 것"
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### goal.scope.no-code-fix
- 제목: 서비스는 알려 주는 데까지만 하고 코드는 고치지 않는다
- 값: 서비스는 바뀐 내용을 알려 주는 데까지만 하고, 코드를 고치도록 지시하거나 고친 결과를 검사하지 않는다
- 이유: 코드를 고치는 일은 AI와 사람의 몫이고, 서비스가 맡으면 이번 범위를 넘는다
- 적용 범위: 코드: apps/mcp-server/src/tools/notify/** / 코드: apps/mcp-server/src/hooks/**
- 근거: Linear SIL-98 (호윤님 결정, 10/14)
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### goal.metric.primary
- 제목: 주 지표는 "몰랐다"고 답한 변경 수다
- 값: 알림을 받은 사람이 "관계있다"와 "몰랐다"를 함께 답한 확인할 변경의 수를 주 지표로 센다
- 이유: 바뀐 기준을 모르고 일하는 문제가 실제로 있는지 직접 보여 주는 숫자다
- 적용 범위: 화면: 지표 / 코드: packages/cli/src/export/** / 문서: 사일로 OKR과 지표
- 근거: 사일로 OKR과 지표 KR1 · PRD-05 "목표 숫자"
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### goal.metric.team-split
- 제목: 우리 팀 숫자와 다른 팀 숫자는 나눠서 센다
- 값: 지표는 우리 팀과 다른 팀을 따로 집계하고, 합친 숫자만 보여 주지 않는다
- 이유: 우리 팀은 매일 대화해서 "몰랐다"가 낮게 나올 수 있어 섞으면 문제의 크기가 흐려진다
- 적용 범위: 화면: 지표 / 문서: 발표 자료
- 근거: 사일로 OKR과 지표 "숫자를 읽을 때 주의할 점"
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### goal.metric.funnel
- 제목: 바뀐 기준이 담당자에게 닿는 5단계를 각각 센다
- 값: 바뀐 기준 수, AI가 찾아 고친 수, 알림을 보낸 이슈 수, 관계있다 수, 몰랐다 수를 단계별로 센다
- 이유: 어느 단계에서 줄어드는지 봐야 어디를 고칠지 안다
- 적용 범위: 화면: 지표 / 코드: packages/cli/src/export/**
- 근거: 사일로 OKR과 지표 "단계별로 보는 숫자" · PRD-05
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### goal.metric.missed
- 제목: 도구가 놓친 변경을 따로 센다
- 값: 위키에 반영되지 않았다가 Git 기록이나 Slack에서 나중에 발견된 변경 수를 매일 따로 센다
- 이유: 놓친 수가 많으면 규칙만으로는 부족하고 자동으로 찾는 기능이 필요하다는 근거가 된다
- 적용 범위: 문서: CHANGELOG.md / 화면: 지표
- 근거: v0 도그푸딩 가이드 "매일 보는 숫자" · 사일로 OKR과 지표
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### goal.guard.check-time
- 제목: 알림 하나를 확인하는 시간은 중간값 1분 이내다
- 값: 알림을 연 순간부터 답할 때까지 걸린 시간의 중간값을 60초 이내로 지킨다
- 이유: 1분을 넘기면 사람들이 알림을 읽지 않고 넘긴다
- 적용 범위: 화면: 터미널 알림, 나에게 온 변경 / 화면: 지표
- 근거: 사일로 OKR과 지표 "보호 지표"
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### goal.guard.unrelated-rate
- 제목: "관계없다" 비율을 보호 지표로 본다
- 값: 전체 답 중 "관계없다"의 비율을 매일 보고, 오르면 이슈 연결과 적용 범위를 점검한다
- 이유: 이 비율이 높으면 엉뚱한 사람에게 알림이 가고 있다는 뜻이다
- 적용 범위: 화면: 지표 / 코드: packages/mcp/src/tools/link_task*
- 근거: 사일로 OKR과 지표 "보호 지표"
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### goal.guard.revert-rate

- 값: AI가 고친 기준 중 사람이 되돌린 비율을 매일 보고, 오르면 바뀐 기준 찾기의 판단 규칙을 점검한다
- 이유: 이 비율이 높으면 AI가 기준을 자주 틀리게 고친다는 뜻이다
- 적용 범위: 화면: 지표 / 코드: packages/detect/src/judge/**
