# 기능: 담당자에게 알리기 (notify)

> **영역 요약:** 이슈 연결, 영향받는 담당자 찾기, 터미널 알림, 응답, 예외 처리
> **관련 문서:** 스펙: 담당자에게 알리기, PRD-03, PRD-04 기능 3
> **DRI:** 민수님 (디자인: 부건님)

### notify.link.human-confirm
- 제목: 이슈와 기준의 연결은 사람이 확인해야 저장된다
- 값: AI는 관련 기준 후보를 제안만 하고, 사람이 맞다고 한 것만 이슈와 기준 연결로 저장한다
- 이유: 잘못 연결되면 관계없는 사람에게 알림이 가서 관계없다 비율이 올라간다
- 적용 범위: 코드: packages/mcp/src/tools/link_task*
- 근거: MVP 범위 "이슈와 기준 연결"
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### notify.link.no-guess
- 제목: 연결이 없는 이슈는 "근거 없음"으로 표시한다
- 값: 도구는 이슈와 기준의 연결을 임의로 만들지 않고, 연결이 없는 이슈는 근거 없음으로 표시한다
- 이유: 추측으로 연결하면 알림이 틀린 사람에게 간다
- 적용 범위: 코드: packages/mcp/src/tools/link_task* / 화면: 요약 화면
- 근거: PRD-04 기능 3 "작업과 기준 연결"
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### notify.target.include-done
- 제목: 완료된 이슈의 담당자에게도 알린다
- 값: 바뀐 기준과 이어진 이슈가 완료 상태여도 담당자에게 확인할 변경을 만든다
- 이유: 이미 만든 결과물이 바뀐 기준과 달라졌을 수 있다
- 적용 범위: 코드: packages/mcp/src/tools/notify*
- 근거: PRD-04 기능 3 "영향받는 작업 찾기"
- 항상 적용: 아니오
- 상태: 사용
- 버전: 1

### notify.target.skip-author
- 제목: 기준을 바꾼 본인에게는 알리지 않는다
- 값: 기준을 바꾼 사람에게는 그 변경에 대한 확인할 변경을 만들지 않는다
- 이유: 본인은 이미 알고 있어서 알림이 소음이 된다
- 적용 범위: 코드: packages/mcp/src/tools/notify* / 코드: packages/cli/src/brief/**

### notify.pending.one-per-issue
- 제목: 확인할 변경은 이슈마다 하나씩 만든다
- 값: 기준 하나가 바뀌면 그 기준과 이어진 이슈마다 확인할 변경을 하나씩 만든다
- 이유: 이슈 단위로 답을 받아야 어떤 작업이 영향받았는지 셀 수 있다
- 적용 범위: 코드: packages/mcp/src/tools/notify*

### notify.pending.merge-versions
- 제목: 확인 전에 같은 기준이 또 바뀌면 최신 버전 하나로 합친다
- 값: 같은 이슈에 같은 기준의 확인 안 한 이전 버전이 있으면 이전 것은 새 버전으로 대체됨으로 닫고, 담당자가 마지막으로 확인한 버전과 최신 버전을 비교해 보여 준다
- 이유: 중간 버전을 하나씩 보여 주면 알림이 쌓이고 전체 차이를 알기 어렵다
- 적용 범위: 코드: packages/mcp/src/tools/notify* / 화면: 터미널 알림, 나에게 온 변경

### notify.pending.no-owner
- 제목: 담당자 없는 이슈는 알림을 만들지 않고 건너뛴다
- 값: 담당자가 없는 이슈에는 확인할 변경을 만들지 않고 건너뛴다
- 이유: 받을 사람이 없는 알림은 나중에 옮기지 않고 건너뛰기로 정했다

### notify.pending.owner-change
- 제목: 이슈 담당자가 바뀌면 남은 확인할 변경을 새 담당자에게 옮긴다

- 이유: 새 담당자가 바뀐 기준을 모른 채 일하게 되는 것을 막는다
