## 1. 결정한 모양

**1건**

```
● [app] SIL-67 관련 결정 사항 변경이 1건 있어요.

  앱 알림 제목은 32자 이하로 쓴다
    공백 포함 [40]자 이하
  ↳ 공백 포함 [32]자 이하
```

**여러 건** (변경마다 구분선으로 나눠요)

```
● [detect, work] SIL-66 관련 결정 사항 변경이 총 2건 있어요.
  ----------------------------------------------------------------------------
  AI가 고친 기준에는 PR 번호와 바뀐 줄을 이유에 남긴다
    AI가 기준을 고치면 [근거] 칸에 PR 번호와 판단에 쓴 바뀐 코드 줄을 적는다
  ↳ AI가 기준을 고치면 [이유] 칸에 PR 번호와 판단에 쓴 바뀐 코드 줄을 적는다
  ----------------------------------------------------------------------------
  리뷰 요청은 4시간 안에 본다 (폐기)
    코드 리뷰 요청은 4시간 안에 보고, 못 보면 못 본다고 남긴다
  ----------------------------------------------------------------------------
```

**종류별 모양**

| 종류             | 제목 줄         | 값 줄                                       |
| ---------------- | --------------- | ------------------------------------------- |
| 일반 (작게 바뀜) | 제목            | 이전 값 / `↳` 지금 값. 바뀐 부분만 `[ ]`    |
| 일반 (크게 바뀜) | 제목            | 이전 값 / `↳` 지금 값. 대괄호 없이 그대로   |
| 단어를 지움      | 제목            | 이전 줄 `[근거,]`, 지금 줄 `[]` (빈 대괄호) |
| 되돌림           | 제목 `(되돌림)` | 일반과 같아요                               |
| 신규             | 제목 `(신규)`   | `↳` 지금 값 한 줄                           |
| 폐기             | 제목 `(폐기)`   | 이전 값 한 줄 (`↳` 없음)                    |

## 2. 작성 규칙

| 항목         | 규칙                                                                                                          |
| ------------ | ------------------------------------------------------------------------------------------------------------- |
| 1건일 때     | 첫 줄 다음에 빈 줄 하나, 그다음 변경                                                                          |
| 여러 건일 때 | 첫 줄 다음, 변경 사이, 마지막에 구분선. 구분선은 `-`를 화면 너비에 맞춰 이어요 (80칸에서 76개, 2칸 들여 쓰기) |
| 변경 순서    | 위키 목차 순서 (영역 순서와 같아요)                                                                           |
| 제목 줄      | 2칸 들여 쓰기. 넘치면 끝을 `…`. 태그가 있으면 태그는 남기고 제목을 줄여요                                     |
| 태그         | 한 단어 명사를 괄호로 감싸 제목 끝에: `(신규)` `(폐기)` `(되돌림)`                                            |
| 이전 값 줄   | 앞에 빈칸 4개                                                                                                 |
| 지금 값 줄   | 앞에 ` ↳`                                                                                                     |

**바뀐 부분 찾기**

- 이전 값과 지금 값의 앞뒤 공통 부분을 걷어내고, 가운데 다른 부분만 `[ ]`로 감싸요.
- 값이 짧고 단어 안에서 바뀌면 글자 단위로 찾아요 (`40자` → `[40]자`).
- 긴 값은 단어 단위로 찾아요.
- 줄이 넘치면 **앞쪽**을 `…`로 잘라요. 바뀐 부분에 가까운 쪽을 남겨요.
- 이전 줄과 지금 줄의 `[`는 같은 칸에서 시작해요.
- **바뀐 부분이 값의 절반을 넘으면** 대괄호 없이 값을 처음부터 그대로 보여 주고, 넘치면 끝을 `…`로 잘라요. 절반이라는 기준은 Claude 제안이에요 (6장).

## 3. 이렇게 정한 이유

### 3-1. 제목을 위에 두고, 아래 두 줄은 값을 비교해요 (결정)

- 제목 아래에서 무엇이 어떻게 바뀌었는지를 보여 줘요.
- 제목끼리 비교하던 이전 시안은 제목이 그대로이고 값만 바뀐 경우에 두 줄이 똑같아지는 문제가 있었어요.

### 3-2. 이전 → 지금 순서 (결정)

- 시간 순서대로 읽혀서 이해하기 쉬워요.

### 3-3. 바뀐 부분만 대괄호로 (결정)

- 이전과 지금은 문장 구조가 거의 같아서, 바뀐 곳만 눈에 띄면 돼요.
- 색이나 굵게가 안 나오는 터미널에서도 대괄호만으로 바뀐 곳이 보여요.

### 3-4. 크게 바뀌면 값을 그대로 (결정)

- 샘플 데이터와 Linear 실제 변경 11개로 그려 보니, 5개(C2, C5, C7, PWA 전환, 브랜치 규칙)가 문장을 통째로 바꾼 변경이었어요.
- 이런 경우 대괄호가 거의 전부를 덮어서 강조 효과가 없고, 앞쪽이 `…변경이`처럼 잘려 주어가 사라지고, 뒤쪽이 잘리면 닫는 `]`도 사라졌어요.
- 대괄호 없이 값을 처음부터 보여 주면 적어도 문장의 시작은 온전히 읽혀요.

### 3-5. 단어를 지우면 빈 대괄호 (결정)

- 지운 자리를 `[]`로 남겨서, 무엇이 빠졌는지 위아래로 비교할 수 있어요.
- 실제 예: SIL-64의 `notify.terminal.show-fields`에서 "근거,"를 빼는 변경이에요.

### 3-6. 신규·폐기·되돌림은 태그로 (결정)

- 한 단어 명사로 짧게 붙여서, 제목을 읽으면서 종류를 함께 알 수 있어요.
- 괄호를 쓰는 이유는 두 가지예요. 대괄호는 이미 영역과 바뀐 부분 표시에 쓰고 있어요. 그리고 Primer 가이드가 라벨을 괄호로 표시해요(이슈의 `(완료)`와 같은 방식).
- "새로 생김"은 두 단어라 한 단어 명사인 "신규"로 했어요 (Claude 제안, 부건 확인 필요).
- 태그를 제목 끝에 둬서, 여러 건일 때도 제목이 모두 같은 칸에서 시작해요.
- 폐기는 지금 값이 없어서 이전 값 한 줄만 보여 줘요. 무엇이 없어지는지가 보여요.
- SIL-64의 실제 변경 약 19개 중 10개 이상이 폐기예요. 실제로 가장 먼저, 가장 많이 받게 될 알림이에요.

### 3-7. 구분선은 여러 건을 나누는 용도 (결정)

- 1건일 때는 구분선 없이 빈 줄 하나로 첫 줄과 변경을 나눠요.
- 2건 이상일 때 변경과 변경 사이를 나눠요.
- `-`(영문 하이픈)는 어떤 터미널 설정에서도 1칸이라 줄이 꺾이지 않아요. 미리보기에서 한국어 코딩 글꼴(나눔고딕코딩)이 상자 선 `─`를 2칸으로 그리는 것을 확인했어요.

### 3-8. 지금 줄에 `↳` (결정)

- "바뀌어서 이렇게 됐다"로 읽혀서, 개발 관례를 모르는 사람에게도 통해요.
- 어떤 터미널 설정에서도 1칸이에요. 미리보기(xterm.js)에서 정상으로 보이는 것을 확인했어요.

### 3-9. 이슈 줄은 뺐어요 (결정)

- 이슈 코드는 첫 줄에 있어요. 이슈 제목은 T3에서 보여 줘요.

## 4. 버린 시안과 이유

| 순서 | 시안                                                            | 버린 이유                                                      |
| ---- | --------------------------------------------------------------- | -------------------------------------------------------------- |
| 1    | 3줄 요약: 제목 / `이전 값 → 지금 값` 한 줄 / `내 이슈: …`       | 값이 길면 화살표 양쪽이 잘린 조각만 남아요                     |
| 2    | 이름표 줄: `지금 제목` / `이전 제목` / `이슈 …` (제목끼리 비교) | 제목은 그대로이고 값만 바뀐 변경이면 두 줄이 똑같아져요        |
| 3    | 제목 / `누가 · 언제 · 이전: 이전 제목` / 이슈                   | 한 줄에 덩어리가 4개라 읽을 부담이 커요                        |
| 4    | 이름표 줄의 순서 `지금 → 이전`                                  | 시간 순서(`이전 → 지금`)가 이해하기 쉬워요                     |
| 5    | 값 전체를 `-` / `+` 두 줄로                                     | 값이 길면 두 줄이 똑같이 잘려서 차이가 안 보여요               |
| 6    | 한 줄 안에 `[이전 → 지금]`                                      | 긴 값이면 대괄호 안이 길어서 한 줄 안에서 오가며 읽어야 해요   |
| 7    | 기호 `-` / `+`                                                  | 개발 관례라 디자이너에게는 "빼기/더하기"로 읽힐 수 있어요      |
| 8    | 기호 `<` / `>`                                                  | 개발자에게만 익숙해요                                          |
| 9    | 기호 `○` `●` `◇` `◆` `□` `■` `▷` `▶` `→`                        | 한국어 터미널 설정에서 2칸이 돼 줄이 밀려요                    |
| 10   | 기호 `✗` / `✓`                                                  | "이전 값이 틀렸다"로 읽혀요                                    |
| 11   | 이슈 줄을 두고 커서를 올리면 내용 보기                          | 터미널에는 마우스를 올렸을 때 원하는 글을 띄우는 기능이 없어요 |
| 12   | 구분선 `────` (상자 선)                                         | 한국어 터미널 설정이나 한국어 코딩 글꼴에서 2칸이 돼 넘쳐요    |
| 13   | 1건일 때도 위아래 구분선                                        | 구분선은 여러 건을 나누는 용도로 쓰기로 했어요                 |
| 14   | 폐기를 `↳ [폐기됨]` 줄로 표시 (임시안)                          | 태그로 정했어요                                                |
| 15   | 크게 바뀌어도 대괄호 유지                                       | 강조 효과가 없고 앞뒤가 잘려 읽기 어려워요 (3-4)               |
