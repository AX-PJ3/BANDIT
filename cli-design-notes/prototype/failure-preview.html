정할 것

  1. 답 기록 실패와 이슈 반영 실패를 어디서 띄울지

    민수님 · 지금은 기록 뒤 단계가 실패하면 조용히 끝나요. 실패한 도구 뒤에 hooks 글을 띄울 수 없으면 Claude가 정해진 문장을 그대로 쓰게 안내문에 넣어요

  2. 바꾼 문구를 언제 반영할지

    부건님·민수님 · 서버가 만드는 글(screens.ts, hooks 안내)은 서버를 다시 올리면 바로 바뀌어요. 서버에 아예 못 붙을 때 뜨는 글과 설정 파일·토큰 문장은 각자 컴퓨터의 hook.mjs에 있어서 팀원 모두 pnpm mcp:register를 다시 돌려야 해요. 작업 뒤 한 줄(Stop) 결정과 같은 때 묶으면 재설치가 한 번이에요

  3. 실패가 계속되면 입력할 때마다 띄울지

    부건님 · 지금은 매번 떠요. 실패를 "변경 없음"으로 숨기지 않는 게 원칙이라 매번 두는 쪽을 추천해요

화면 글 원본은 cli-design-notes/prototype/notify-prototype/proto/notice.py의 failed_* 함수(제안)와 apps/mcp-server/hooks-client/haribo-hook.mjs의 FAILED_NOTICE(지금)예요. 선택 화면, Claude 문장, 머리줄은 근사예요.
