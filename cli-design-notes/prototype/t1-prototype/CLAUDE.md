# T1 시안: 결정 사항 등록

이 폴더는 터미널 화면 T1(결정 사항 등록)을 실제 Claude Code에서 보는 시안이에요. 결정은 [../../T1-결정-사항-등록-결정기록.md](../../T1-결정-사항-등록-결정기록.md), 확인할 케이스는 [../../T1-테스트-케이스.md](../../T1-테스트-케이스.md)에 있어요.

## 이 폴더에서 지킬 것

- 결정 사항은 MCP 서버 `wiki`에만 있어요. 저장소의 `team-wiki/` 파일과 CHANGELOG는 읽지도 고치지도 않아요.
- 지금 대화하는 사람은 부건이에요.
- **다른 결정 사항 화면과 등록될 모습은 hooks가 직접 띄워요.** `show_conflicts`, `preview_standard`를 부른 뒤에는 그 내용을 글로 다시 쓰거나 요약하지 않아요. "정리해서 보여드렸어요" 같은 말도 쓰지 않아요. 도구를 부른 바로 다음에 아무 글 없이 선택 화면(AskUserQuestion)을 띄워요.
- hooks가 띄우는 글 맨 위에는 Claude Code가 `PostToolUse:mcp__wiki__… says:` 머리글을 붙여요. 바꿀 수 없어요. 화면 글(`proto/screens.py`)은 첫 줄을 비워서 머리글 바로 아래부터 시작하게 했고, Claude는 이 머리글을 따로 쓰거나 옮기지 않아요.
- 아래 `" "` 안의 문구는 글자 그대로 써요.
- 결정 사항과 다른 것을 "충돌"이라고 부르지 않아요. 팀 위키에서 "충돌"은 두 사람이 같은 버전을 동시에 바꾼 상황이에요. "다른 결정 사항", "달라요"라고 써요.

## 흐름

### 경우 1 · 작업하다가 결정 사항과 다른 값을 쓰게 될 때

1. 코드를 고치기 **전에** `search_standards`로 관련 결정 사항을 찾아요.
2. 부탁받은 작업과 다른 결정 사항이 있으면 `show_conflicts`를 불러요. `kind`는 `작업`, `request`는 부탁받은 작업을 한 줄로, `value`는 바꾸려는 결정 사항에 등록할 새 값이에요(아래 "되돌림").
3. AskUserQuestion — header `결정 사항 등록`, question `기존 결정 사항과 다른 작업이에요. 그래도 진행할까요?`

   | label  | description                                                            |
   | ------ | ---------------------------------------------------------------------- |
   | 예     | 결정 사항을 등록하고 작업을 진행할게요. 등록될 모습 먼저 보여 드릴게요 |
   | 아니요 | 부탁하신 작업은 멈춰 둘게요. 기존 결정 사항은 그대로 유지할게요        |

4. 예 → 아래 "등록될 모습"으로. 아니요 → `기존 결정 사항을 그대로 유지할게요. 다른 작업을 시작해 주세요.`라고 쓰고 끝내요. 코드를 고치지 않아요(새 값을 이번 작업에만 쓰는 길은 없어요). Esc로 닫으면 아니요가 아니라 취소하기예요(아래 "등록될 모습" 5번).

### 경우 2 · 사람이 결정 사항을 새로 만들거나 바꿔 달라고 할 때

1. `search_standards`로 관련 결정 사항을 찾아요.
2. `show_conflicts`를 불러요. `kind`는 `요청`, `request`는 요청을 한 줄로, `value`는 등록할 새 값이에요. 다른 결정 사항이 없으면 `conflicts`는 빈 배열이에요.
3. 묻지 않고 바로 아래 "등록될 모습"으로 가요. 그만둘 기회는 등록될 모습의 취소하기예요. 단, `show_conflicts` 결과에 `revert`가 있으면 아래 "되돌림"대로 먼저 물어요.

### 다른 결정 사항을 나누는 법 (`conflicts`)

- `변경`: 같은 것을 다르게 정한 결정 사항이에요. 이 결정 사항의 새 버전으로 등록해요(ID 그대로).
- `어긋남`: 다른 결정 사항인데 새 값과 같이 지킬 수 없어요. 보여만 주고 같이 고치지 않아요. 범위가 겹치는 것(넓은 결정 사항과 좁은 결정 사항), 항상 적용 결정 사항과 부딪히는 것, 이 값에 기대어 정한 결정 사항도 모두 `어긋남`으로 보고, 무엇 때문인지는 `why`에 써요.
- `why`: 왜 그렇게 판단했는지 한 문장이에요. 화면에는 결정 사항 제목 바로 아래에 나와요. 그 결정 사항의 무엇이 새 값과 맞지 않는지 드러나게 써요. 예: `40자 이하로 정한 길이를 32자 이하로 다시 정해요`, `결정 사항 제목(최대 40자)을 그대로 쓰면 32자에서 잘려요`.
- 낱말만 겹치고 내용이 맞지 않는 게 아니면 넣지 않아요.

### 되돌림 (시안 10/16)

새 값이 그 결정 사항의 예전 버전 값과 같은지는 **서버가 판단해요.** Claude는 `conflicts`에 바꾸는 결정 사항을 지금처럼 `변경`으로 넣고, `show_conflicts`의 `value`에 새 값을 넣기만 해요. 결과에 `revert`가 있으면 hooks가 그 줄을 보라 "되돌림"으로 바꿔 맨 아래에 보여 줘요(되돌아가는 버전·누가·언제·이유, 머리표 아래 기존 결정 사항 한 줄). Claude는 이 내용을 글로 다시 쓰지 않아요.

- 경우 1: 지금처럼 `그래도 진행할까요?`를 물어요.
- 경우 2: 묻지 않고 넘어가지 않아요. AskUserQuestion — header `결정 사항 등록`, question `기존 결정 사항을 되돌리는 작업이에요. 그대로 진행할까요?`, 보기는 경우 1의 3번 표와 같아요. 예 → "등록될 모습"으로. 아니요 → `기존 결정 사항을 그대로 유지할게요. 다른 작업을 시작해 주세요.`라고 쓰고 끝내요. Esc로 닫으면 취소하기와 같아요("등록될 모습" 5번).
- 시안에서는 `T1_DATA=revert claude`로 켜요. `app.notify.title-length`가 v1 40자 → v2 32자 → v3 40자(지금)라서 32자로 바꾸면 v2로 되돌리는 거예요.
- 폐기된 결정 사항은 넣지 않아요.

### 등록될 모습

1. 제목·값·이유·항상 적용을 정리해요.
   - 제목은 새 값에 맞게 고쳐요(40자 이하). 값·이유는 120자 이하예요.
   - 이유는 **이번 대화에서 사람이 한 말에 근거가 있을 때만** 정리해 넣어요. 작업 내용이나 다른 결정 사항의 이유만으로 지어내지 않아요. 근거가 없으면 `preview_standard`를 부르기 전에 `이 결정 사항을 바꾸는 이유를 작성해 주세요. 작성해 주신 내용을 기반으로 정리해 드릴게요.`라고 쓰고 입력을 기다려요. 받은 글은 한 문장으로 정리해 넣고, 다시 확인하지 않아요.
   - 항상 적용은 모든 작업에 매번 지켜야 할 때만 `true`예요. 대부분 `false`예요.
   - 새 결정 사항의 ID는 `영역.주제.규칙`(영문 소문자·숫자·하이픈)이에요.
2. `preview_standard`를 불러요. 오류가 오면 그 문장대로 고쳐서 다시 불러요.
3. AskUserQuestion — header `결정 사항 등록`, question `이대로 등록할까요?`. 경우 2에서 `show_conflicts`의 `conflicts`가 1개 이상이었으면 question은 `달라지게 되는 기존 결정 사항 내역을 확인했나요? 이대로 등록할까요?`예요. 단, 경우 2에서 되돌림으로 이미 물었고 `어긋남`이 없으면 `이대로 등록할까요?`예요.

   | label    | description                                                                                                                                     |
   | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
   | 등록하기 | `preview_standard` 결과의 `notify_count`가 1 이상이면 `결정 사항을 저장하고 연결되어 있는 이슈 담당자에게 알려요`, 0이면 `결정 사항을 저장해요` |
   | 수정하기 | 수정할 내용을 말해 주세요                                                                                                                       |
   | 취소하기 | 결정 사항 등록을 취소해요. 기존 결정 사항을 유지해요                                                                                            |

4. 등록하기 → `save_standard`를 불러요(바꾸는 결정 사항이면 `base_version`에 지금 버전). 수정하기 → `어떤 부분을 수정할까요?`라고 묻고, 고친 뒤 `preview_standard`부터 다시. 취소하기 → 등록하지 않아요. 결정 사항은 그대로예요. 하던 작업이 있으면 `결정 사항 등록을 취소했어요. 기존 결정 사항이 유지돼 하던 작업은 멈춰 둘게요. 어떻게 진행할지 알려 주세요.`라고 쓰고 코드를 고치지 않은 채 멈춰요. 사람이 다음에 말한 대로 해요. 하던 작업이 없으면 `결정 사항 등록을 취소했어요. 결정 사항은 그대로예요.`만 써요.
5. 선택 화면을 Esc로 닫으면(`User declined to answer questions`) **취소하기와 같아요.** 경우 1의 첫 질문(`그래도 진행할까요?`)과 위 3번 질문 모두 그래요. 아니요로 치지 않아요. Esc를 누른 바로 그때는 Claude Code가 요청을 멈춰서 Claude에게 차례가 오지 않아요. 사람이 다음에 말하면 그 말에 답하기 전에 위 4번의 취소하기 문구를 먼저 그대로 써요. 등록하지 않고, 코드를 고치지 않은 채 멈추고, 그 문구 말고 다른 안내나 질문을 덧붙이지 않아요. 다음 말이 `계속해 줘`처럼 어떻게 할지 분명하지 않으면 아무것도 하지 않고 기다려요. 결정 사항을 바꾸라는 말이면 T1을 처음부터 다시 해요.

### 등록 완료

`save_standard`가 성공하면 hooks가 등록 완료 글을 띄워요. Claude는 그 글을 옮기지 않아요. 하던 작업이 있으면 `하던 작업을 이어갈게요.`를 쓰고 이어가고, 없으면 `등록을 마쳤어요.` 한 줄만 써요.

`save_standard`가 오류를 돌려주면 오류 문장을 그대로 보여 주고, 그 문장이 말하는 대로 다시 조사하거나 사람에게 물어요. 단, 그 사이 결정 사항이 바뀌었다는 오류는 아래 "저장하는 사이 먼저 바뀜"대로 해요.

## 예외 (10/14 확정)

예외 상태 줄은 실제 화면에서 왼쪽 막대 + 색 글자로 보여요(hooks가 띄울 모양, 결정기록 4-2). 시안은 아직 hooks로 띄우지 못해서 Claude가 아래 문구를 글로 써요.

### 조사 실패 (예외 3)

`search_standards`나 `show_conflicts`가 결정 사항을 불러오지 못했다는 오류를 돌려주면, "다른 결정 사항 없음"으로 보고 넘어가지 않아요. 아래 두 줄만 그대로 쓰고 끝내요(실제 화면: 첫 줄 빨간 막대 + 빨간 글자). 등록하지 않고, 하던 작업도 멈춰요(코드를 고치지 않아요). 스스로 다시 부르지 않아요.

`다른 결정 사항을 조회하지 못해 하던 작업을 멈췄어요.`
`잠시 뒤 다시 시도해 보시고 반복된다면 담당자에게 알려 주세요.`

하던 작업이 없을 때(경우 2)는 첫 줄만 `다른 결정 사항을 조회하지 못해 등록을 멈췄어요.`로 바꿔 써요(실제 화면: 빨간 막대 + 빨간 글자).

시안에서는 `T1_FAIL=search claude`로 켜면 `search_standards`가 실패해요.

### 이미 같은 결정 사항 (충돌 3)

- **완전히 같을 때**(같은 ID·같은 값): 선택 화면 없이 `같은 결정 사항이 있어서 등록하지 않았어요.`를 쓰고(실제 화면: 빨간 막대 + 빨간 글자), 다음 줄에 그 결정 사항을 `[영역] 제목 · 값`으로 쓰고 끝내요. 실제로는 서버가 판단해요. 시안 서버는 아직 이 판단을 하지 않아서, `search_standards` 결과로 Claude가 비교해요.
- **뜻이 같을 때**(Claude가 판단): `같은 뜻의 결정 사항이 이미 있어요.`를 쓰고(실제 화면: 노란 막대 + 노란 글자), 다음 줄에 그 결정 사항을 `[영역] 제목 · 값`으로 써요. 그다음 AskUserQuestion — header `결정 사항 등록`, question `그래도 새 결정 사항으로 등록할까요?`, 보기 label `예`(description `등록해요`) / `아니요`(description `등록하지 않아요`)(제안 문구, 시안).
  - 예 → 새 ID로 "등록될 모습"에 가요. 기존 ID를 쓰지 않아요(같은 ID로 새 결정 사항을 저장하면 거절돼요).
  - 아니요 → `등록하지 않았어요. 기존 결정 사항을 그대로 둘게요.`를 쓰고 끝내요(실제 화면: 막대 + 기본 글자색).

### 저장하는 사이 먼저 바뀜 (예외 7)

`save_standard`가 그 사이 결정 사항이 바뀌었다고 거절하면 아래 문구를 그대로 쓰고(실제 화면: 노란 막대 + 노란 글자), 다른 결정 사항 확인(①②)부터 다시 해요(`search_standards` → `show_conflicts`). 사람은 다시 뜬 화면에서 수정하기·취소하기로 다른 내용을 다시 시도할 수 있어요.

`저장하는 사이 다른 사람이 먼저 이 결정 사항을 바꿨어요. 바뀐 내용을 다시 확인할게요.`

### 아니요 뒤 같은 값 (예외 11)

"같은 작업"은 사람이 프롬프트로 시작한 작업 하나예요. 아니요를 고르면 그 작업을 멈춰요. 그 작업 안에서는 같은 값을 다시 쓰지 않으니 다시 묻지 않아요. 사람이 새 프롬프트를 보내면 새 작업이라, 같은 값이 나오면 처음부터 다시 물어요. 아니요 뒤 문구는 위 경우 1의 4번 그대로예요.
