# SIL-68 터미널 알림 · 사내 테스트 진행 대본

- 작성: 2026-10-12 · 부건 (Claude와 대화하며 정리)
- 대상: 터미널 알림 시안 (`cli-design-notes/prototype/notify-prototype`)
- 한 사람당: 약 25분 (진행자 1명, 기록자 1명이면 좋아요. 혼자면 화면 녹화로 대신해요)

## 1. 알고 싶은 것

| 질문                                 | 무엇으로 보나                                                  | 기준 (제안)                            |
| ------------------------------------ | -------------------------------------------------------------- | -------------------------------------- |
| **① 변경 내역을 얼마나 잘 이해하나** | 화면을 가리고 "무엇이 무엇으로 바뀌었나요?"에 맞게 답하는지    | 변경·이유 정답률 80% 이상              |
|                                      | 상세가 뜬 때부터 관계를 고를 때까지 걸린 시간                  | 변경마다 1분 안 (프로젝트 가설)        |
|                                      | 일부러 넣은 관계없는 변경을 "관계없다"로 고르는지              | 정답과 같은 답 80% 이상                |
|                                      | 어느 줄을 보고 판단했나, 어떤 말이 헷갈렸나                    | 안 보는 줄, 헷갈린 말 목록             |
| **② 답하는 게 얼마나 덜 귀찮나**     | 변경 한 건에 답하는 데 걸린 시간, 전체 시간                    | 5건 전체 3분 안                        |
|                                      | 과제 직후 "얼마나 쉬웠나요?" 1~7점 (SEQ)                       | 5.5점 이상                             |
|                                      | "다음에도 이 알림에 답할 것 같나요?" 1~5점                     | 4점 이상                               |
|                                      | Esc로 닫은 횟수, "Type something."·"Chat about this"를 쓴 횟수 | 보기가 부족하거나 귀찮다는 신호로 봐요 |
|                                      | 닫은 뒤 한 줄 알림을 보고 혼자 `결정 사항 확인`으로 돌아오는지 | 도움 없이 돌아오는 사람 비율           |

이번에는 지금 시안이 위 기준을 넘는지와, 가장 많이 걸린 곳 세 군데를 찾는 게 목표예요. 사람 수가 적어서 숫자는 방향을 보는 용도로만 써요.

## 3. 준비

### 3-1. 참가자별 테스트 데이터 (하루 전)

참가자가 **실제로 맡은 이슈**에 이어진 변경 5건을 만들어요. 관계 판단이 진짜여야 해서요. 아래 종류를 섞고, 변경마다 정답(관계있다 / 관계없다)을 미리 정해 둬요.

| #   | 종류                   | 예                                   | 정답 정하는 법                         |
| --- | ---------------------- | ------------------------------------ | -------------------------------------- |
| 1   | 숫자 하나가 바뀜       | 알림 제목 40자 → 32자                | 참가자 이슈와 직접 닿는 것 → 관계있다  |
| 2   | 단어를 지움            | 알림에서 "근거," 빼기                | 닿는 것                                |
| 3   | 문장을 새로 씀         | 리뷰 규칙을 본인 머지로              | 애매한 것 하나 (판단 이유를 들어 봐요) |
| 4   | 새로 생긴 결정 사항    | 같은 변경은 세 번까지만 넘길 수 있다 | 닿는 것                                |
| 5   | **일부러 관계없는 것** | 참가자 영역과 먼 결정 사항           | 관계없다                               |

- 출처는 "AI 대화"와 "PR · AI가 찾음"을 섞어요. 바꾼 사람은 참가자 본인이 아니게 해요.
- 파일: `notify-prototype/proto/changes-test-<이름>.json` (`changes-demo.json` 모양을 따라요). 정답은 파일에 넣지 않고 기록표에만 적어요.

### 3-2. 자리 준비 (참가자마다, 시작 5분 전)

- [ ] 참가자 컴퓨터, 참가자가 평소 쓰는 터미널과 테마 그대로
- [ ] 터미널 창 크기를 평소대로 두고, 세로 줄 수를 기록표에 적어요 (15줄 확인용, 질문 문서 호윤-14)
- [ ] `cd cli-design-notes/prototype/notify-prototype && ./reset.sh`
- [ ] 화면 녹화 시작 (녹화 동의를 받은 뒤)
- [ ] 기록표 한 장, 초시계
- [ ] **Claude Code는 아직 켜지 않아요.** 참가자가 직접 켜게 해요

켜는 명령 (참가자에게 보여 줄 카드):

```
NOTICE_DATA=changes-test-<이름> claude
```

## 4. 진행 (약 25분)

말할 문장은 `「」` 안에 있어요. 읽듯이 말하지 않아도 되지만, **답을 끌고 가는 말**(관계있다, 몰랐다, 결정 사항이 뭔지 설명)은 하지 않아요.

### 4-1. 시작 (2분)

「시간 내 줘서 고마워요. 오늘은 새로 만드는 도구를 시험하는 거라, 잘하고 못하고는 없어요. 막히면 그건 화면 탓이에요.」

「평소처럼 Claude Code로 일을 시작하는 상황이라고 생각해 주세요. 하면서 보이는 것, 드는 생각을 소리 내어 말해 주시면 큰 도움이 돼요. 저는 옆에서 보기만 하고 되도록 끼어들지 않을게요.」

「화면은 녹화하는데 이 시험에만 쓰고 끝나면 지워요. 괜찮으세요?」

→ 동의를 받아요. 이 도구가 무엇을 하는지는 **설명하지 않아요.**

### 4-2. 과제 1: 평소처럼 작업 시작하기 (8분)

「이 카드의 명령으로 Claude Code를 켜 주세요.」

(켤 때 알림이 뜨면, 기다렸다가)

「평소에 하던 작업을 하나 맡긴다고 생각하고 입력해 주세요. 예를 들면 '로그인 화면 문구 고쳐 줘'처럼요.」

→ 상세와 질문이 뜨면 **아무 말도 하지 않아요.** 5건을 다 답할 때까지 둬요.

**기록할 것** (변경마다, 기록표 6장)

- 상세가 뜬 시각 → 관계를 고른 시각 → 두 번째 답을 고른 시각
- 고른 답과 정답이 같은지
- 소리 내어 말한 것 그대로 (특히 "이게 뭐지", "아 이거" 같은 말)
- 눈이 어디에 머무는지: 제목 / 변경 / 이유 / 이슈 / 출처
- "Type something."이나 "Chat about this"를 썼는지, 쓴 글
- Claude가 질문 사이에 말을 덧붙였는지

**침묵이 20초 넘으면**: 「지금 무슨 생각 하세요?」

**막혀서 2분이 지나면**: 「어떤 게 막히세요?」라고만 물어요. 그래도 못 넘어가면 「Esc를 눌러도 돼요」라고 알려 주고, 기록표에 "도움 줌"을 적어요.

### 4-3. 과제 2: 넘겼다가 다시 돌아오기 (4분)

(`./reset.sh`로 처음 상태로 되돌리고 다시 켜요. 같은 데이터예요)

「이번에는 급한 일이 있어서 지금은 답할 시간이 없다고 생각해 주세요. 원하는 대로 넘어가 보세요.」

→ Esc를 누르는지, 다른 방법을 쓰는지 봐요. 방법을 알려 주지 않아요.

「좋아요, 이어서 다른 작업을 하나 더 입력해 주세요.」

→ 한 줄 알림(`● 확인할 변경 5건 · "결정 사항 확인"을 입력하면 변경 내역을 볼 수 있어요.`)을 알아보는지 봐요.

「이제 시간이 생겼어요. 아까 넘긴 것에 다시 답하려면 어떻게 하시겠어요?」

→ 혼자 `결정 사항 확인`을 입력하는지, 몇 초 걸리는지 적어요. 첫 변경까지만 답하면 돼요.

### 4-4. 이해도 질문 (4분, 화면을 가리고)

터미널 창을 내리거나 노트북 화면을 살짝 덮어요. 과제 1에서 본 변경 중 **1번(숫자)과 3번(문장을 새로 씀)**을 골라 물어요.

1. 「방금 본 변경 중에 [1번 제목 앞부분]이 있었죠. 무엇이 무엇으로 바뀌었는지 기억나세요?」
2. 「왜 바뀌었다고 했나요?」
3. 「누가 바꿨나요?」
4. 「그 변경은 어떤 이슈와 이어져 있었나요?」
5. 「[5번, 관계없는 것]은 왜 관계있다 / 관계없다로 고르셨어요?」

→ 기록표에 맞음 / 반쯤 / 틀림으로 적어요. 정답을 알려 주지 않아요.

화면을 다시 보여 주고:

6. 「이 화면에서 판단할 때 가장 먼저 본 줄은 어디예요? 거의 안 본 줄은요?」
7. 「뜻이 헷갈린 말이 있었나요?」 (안 나오면 짚어서 물어요: 「'결정 사항', '확인할 변경', '출처', '(신규)'는 어떻게 이해하셨어요?」)

### 4-5. 수고 질문 (2분)

카드를 보여 주며 숫자로 답하게 해요.

1. 「답하기 전체가 얼마나 쉬웠나요? 1은 아주 어려움, 7은 아주 쉬움이에요.」 (SEQ)
2. 「실제로 일할 때 이 알림이 오면, 다음에도 답할 것 같나요? 1은 전혀 아니다, 5는 꼭 답한다예요.」
3. 「답하는 데 걸린 시간이 어땠어요? 짧았다 / 적당했다 / 길었다 중에서요.」

### 4-6. 인터뷰 (4분)

1. 「가장 귀찮았던 순간은 언제였어요?」
2. 「질문과 질문 사이에 기다린 시간은 어떻게 느껴졌어요?」
3. 「'이 변경을 이미 알고 있었나요?'에서 고민한 적이 있었나요? 어떤 고민이었어요?」
4. 「보기에 없는 답을 하고 싶었던 적이 있었나요?」
5. 「하나만 바꿀 수 있다면 무엇을 바꾸고 싶어요?」

### 4-7. 마무리 (1분)

「정말 고마워요. 오늘 본 화면은 아직 시안이라 바뀔 거예요. 혹시 나중에 더 생각나는 게 있으면 편하게 알려 주세요.」

→ 녹화를 멈추고 `./reset.sh`로 답 기록을 지워요. `answers.json`은 지우기 전에 참가자 이름으로 복사해 둬요.

## 5. 진행자가 지킬 것

- 도구가 무엇을 하는지, 답이 무엇을 뜻하는지 **먼저 설명하지 않아요.** 설명이 필요했다면 그 자체가 결과예요.
- "관계있다", "몰랐다"처럼 답 이름을 먼저 말하지 않아요.
- 참가자가 물어보면 되물어요: 「어떻게 생각하세요?」
- 참가자가 틀려도 고쳐 주지 않아요. 끝난 뒤 궁금해하면 그때 알려 줘요.
- 시간이 모자라면 4-6 인터뷰를 줄이고, 4-4 이해도 질문은 꼭 해요.

## 7. 결과 정리

1. 참가자별 기록표를 한 표로 모아요. 변경 종류(숫자 / 지움 / 새로 씀 / 신규 / 관계없음)별로 판단 시간과 정답률을 봐요.
2. 1장의 기준과 비교해 넘은 것 / 못 넘은 것을 나눠요.
3. 말한 것과 인터뷰에서 **두 명 이상**이 같은 곳에서 걸린 것을 고칠 거리로 올려요. 고칠 거리마다 어느 화면, 어느 줄인지 적어요.
4. 결과와 고칠 거리를 결정기록 형식(결정 / 제안 / 미정)으로 `cli-design-notes`에 남기고, SIL-68에 링크를 걸어요.
