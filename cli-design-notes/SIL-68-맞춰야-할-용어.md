**남은 일**

- 신지님이 앱에서도 "결정 사항"을 쓸지 확인해요(신지-1). 정민님 웹 앱의 `기준 90개`도 같이 바뀌어요.
- 위키 `copy.term.standard`를 "결정 사항"으로 바꿀지는 호윤님과 정해요(`work.wiki.ask-before-change`). 바꾸면 `용어.md`, `문구.md`, 기준 값 안의 "기준"까지 고칠 곳이 많아요. SIL-64가 "나중에 한 번에"라고 했으니 그때 함께 하는 게 좋아요.
- 상세 맨 위의 "규칙"은 어떤 자료에도 없는 말이라 이미 뺐어요.

## 2. 답해야 하는 바뀐 항목 — "확인할 변경" 외

| 자료                        | 쓰는 말                                                            |
| --------------------------- | ------------------------------------------------------------------ |
| 팀 위키 `용어.md`           | **확인할 변경** (`pending_check`). "확인 대기"는 쓰지 않는 말      |
| 착수 문서                   | 확인할 변경, **답할 변경 개수**, T2 "나에게 온 변경 요약"          |
| 앱 (착수 문서 A2, SIL-74)   | 나에게 온 변경 목록. 안에서 **"답할 변경 / 답한 변경"**으로 나눠요 |
| 터미널 시안 (10/12 고친 뒤) | 확인할 변경                                                        |
| 정민님 시험 문서            | 확인 대기 (상태 줄 `확인 대기 1`)                                  |

터미널 시안에는 켤 때 알림과 닫은 뒤 한 줄에 `변경 내역을 (상세히) 볼 수 있어요`가 남아 있어요. "변경 내역"도 같은 것을 부르는 다른 말이라 `확인할 변경을 볼 수 있어요`처럼 맞추는 게 좋아요.

**남은 일**: 앱 A2의 묶음 이름 "답할 변경 / 답한 변경"이 터미널 "확인할 변경"과 다른 말이에요. 둘 중 하나를 고르거나, 앱은 "답할 / 답한"을 목록 묶음 이름으로만 쓰기로 신지님과 정해요. "나에게 온 변경"은 화면 이름으로만 써요.

## 10. "작업"이 가리키는 것

- 위키 `copy.term.issue`: Linear 할 일은 "이슈"라고 부르고 "작업"이라고 부르지 않아요.
- 터미널 시안의 "작업"은 대부분 **Claude Code에서 지금 하려는 일**이에요(`작업 전에`, `작업을 시작하면`). 이슈를 가리키지 않아서 위키와 부딪히지는 않아요.
- **예외**: "왜 관계없나요?" 보기 3개 중 2개는 "작업"이 이슈를 가리켜요(`내 작업 범위가 아니에요`, `바뀐 부분은 내 작업에 안 쓰여요` 설명). 같은 질문의 다른 보기는 `내 이슈와 연결이 잘못됐어요`라서 한 화면에 "작업"과 "이슈"가 섞여요. `내 이슈 범위가 아니에요`, `바뀐 부분은 내 이슈에 안 쓰여요`처럼 "이슈"로 맞추는 게 좋아요(12번과 함께 신지님과 정해요).
- 위키 `notify.answer.two-questions`도 첫 질문을 "이 변경이 **내 작업**에 영향을 주는지"로 적었어요. 시안 질문은 `이 변경이 내 이슈와 관계가 있나요?`예요. 예전 Spec 문서도 "내 작업에 영향을 주나요?"였어요.
- 정민님 시험 문서와 예전 목업은 이슈를 "작업(T-21)"이라고 불렀어요. 테스트에서 헷갈려하는지 봐요.
