# 터미널 알림 흐름 결정 기록 (켤 때 알림 · 작업 시작 때 상세와 답하기)

- 작성: 2026-10-11 · 부건 (Claude와 대화하며 정리)
- 관련 이슈: SIL-68 [디자인] 터미널 알림과 답하기 화면
- 대상 화면: Claude Code를 켰을 때 뜨는 알림, 작업을 입력했을 때 뜨는 변경 상세와 답하기. 착수 문서의 T2~T5에 해당해요
- 표기: **결정**은 부건이 정한 것, **제안**은 Claude가 낸 의견, **미정**은 아직 정하지 않은 것
- 앞 문서: [T2-첫줄-결정기록.md](T2-첫줄-결정기록.md), [T2-본문-결정기록.md](T2-본문-결정기록.md). 이 문서에서 두 문서와 달라진 점은 7장에 모았어요
- 이어지는 문서: [T3-질문과-답-결정기록.md](T3-질문과-답-결정기록.md). 3-3 질문과 3-4 기록 뒤를 이어서 정했어요(이름표, 알았나 설명, 기록 줄, 닫고 넘어갈 때)
- 단계: **시안 단계**예요. 실제 Claude Code에서 움직이는 시안으로 확인하며 정했지만, 위키 결정 사항으로 올리지는 않았어요

## 1. 이 화면이 하려는 일 (의도)

| 의도                               | 어떻게 지키나                                                                                                                                                                                                                                    |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **작업을 시작하기 전에 알게 한다** | Claude Code를 켜면 바뀐 결정 사항이 있다는 것만 짧게 알려요. 첫 작업을 입력하면 그 작업을 하기 전에 변경 상세를 보여 주고 답을 받아요. 위키 `notify.terminal.session-start`의 이유("작업을 시작하기 전에 알아야 재작업을 막을 수 있다")를 따라요 |
| **글자가 정확하게 나온다**         | 알림과 상세 화면 글은 hooks가 직접 화면에 띄워요. Claude가 옮겨 쓰거나 줄이지 않아요. Claude는 질문을 띄우고 답을 기록하는 일만 해요                                                                                                             |
| **1분 안에 판단한다**              | 무엇이 바뀌었는지를 한 줄로 먼저 보여 주고(`변경  40자 ⭢ 32자`), 그 아래에 지금 값과 이유·이슈·출처를 둬요                                                                                                                                       |
| **답하는 게 귀찮지 않다**          | 모든 답을 고르기만으로 끝낼 수 있어요. "관계없다"의 이유도 보기 3개 중에서 골라요                                                                                                                                                                |
| **사람의 판단을 끌고 가지 않는다** | 기본 선택이나 "추천" 표시를 두지 않아요. 핵심 지표(몰랐다)가 사람의 판단이어야 하기 때문이에요                                                                                                                                                   |
| **어느 터미널에서나 읽힌다**       | 어디서나 1칸인 기호만 쓰고, 78칸 안에 들어가게 하고, 어두운·밝은 터미널 모두에서 보이는 색만 써요                                                                                                                                                |

## 2. 결정한 흐름

```
① Claude Code를 켬
   → hooks(세션 시작)가 회색 알림을 띄움. 답할 변경이 없으면 아무것도 안 띄움
② 사용자가 첫 작업을 입력함
   → hooks(입력할 때)가 첫 변경 상세를 띄움
   → Claude가 선택 화면으로 "관계있다 / 관계없다"를 물음
   → 관계있다 → "알았다 / 몰랐다"   ·   관계없다 → 이유 보기 3개 + 직접 입력
   → 잘 모르겠다 → 기록하지 않고 대기로 남긴 채 다음 변경으로 (10/12 위키, 고른 뒤 흐름은 T3 결정기록 3-5)
   → Claude가 MCP respond로 답을 기록
   → hooks(기록한 뒤)가 "✓ 기록했어요"와 다음 변경 상세를 띄움
③ 모든 변경에 답하면 원래 작업을 시작함
```

- **결정**: 작업을 입력하면 고르는 단계 없이 바로 상세와 질문을 보여 줘요(아래 4장 "방식 2"). 답하기 전에는 작업이 시작되지 않아요.
- **결정**: 화면 글은 정확도가 우선이라 hooks가 직접 띄워요. Claude가 그리는 방식은 쓰지 않아요.
- 실제 구현은 민수님의 MCP 도구 `list_pending`, `respond`를 그대로 쓰는 것을 가정했어요. hooks로 띄우는 부분은 민수님과 확인이 필요해요(8장).

## 3. 결정한 모양

아래에서 `«»`는 형광펜(노란 배경 + 검정 글자), `**`는 굵게, `⟦⟧`는 반전 칩이에요. 화면에는 기호 없이 색으로만 보여요. 예시는 Linear SIL-64의 실제 변경(`notify.terminal.show-fields`에서 "근거," 빼기)이고, 받는 사람은 부건, 이어진 이슈는 SIL-34(완료)와 SIL-35예요.

### 3-1. ① 켤 때

```
 ⎿ SessionStart:startup says:
   ● [notify] 결정 사항이 총 2건 변경되었어요.      ← 숫자 2만 노란 굵은 글자
     작업을 시작하면 변경 내역을 상세히 볼 수 있어요.
```

1건이면 `● [notify] 결정 사항이 1건 변경되었어요.`예요("총"은 2건 이상일 때만).

### 3-2. ② 작업을 입력했을 때: 변경 상세

```
 ⎿ UserPromptSubmit says:
   작업 전에 확인할 변경이 2건 있어요.

   ⟦ 1/2 ⟧
   [notify] 알림에는 이전 값, 지금 값, 이유, 영향받는 이슈를 보여 준다
            호윤님이 오후 6:00에 변경했어요.
     변경  "**근거,**" 삭제

     이유  v2에서는 근거를 화면에 보여 주지 않기로 함
           SIL-34 [알리기] 터미널 알림 첫 시안 (v0용) [완료]
     출처  PR · AI가 찾음
```

- **결정**: 이슈 줄은 `이슈` 이름표 없이 값 칸에만 써요. 칸은 비워 다른 줄의 값 위치에 맞춰요(10/15 부건, 앱·터미널 용어 비교 14번).

### 3-3. 바로 아래에 뜨는 질문 (Claude Code 선택 화면)

| 질문                                          | 선택지 (설명)                                                                                                                                                               |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 이 변경이 내 이슈와 관계가 있나요?            | 관계있다 (내 이슈 결과물이 이 변경에 맞춰 바뀌어야 해요) / 관계없다 (내 이슈와는 상관없는 변경이에요) / 잘 모르겠다 (지금은 판단하기 어려워요. 나중에 답할게요, 10/12 추가) |
| 이 변경을 이미 알고 있었나요? (관계있다일 때) | 알았다 (이 알림 전에 이미 알고 있었어요) / 몰랐다 (이 알림으로 처음 알았어요)                                                                                               |
| 왜 관계없나요? (관계없다일 때)                | 내 작업 범위가 아니에요 / 내 이슈와 연결이 잘못됐어요 / 바뀐 부분은 내 작업에 안 쓰여요                                                                                     |

선택 화면은 질문마다 "Type something.", "Chat about this" 칸을 자동으로 붙여요. 우리가 뺄 수 없어요. 바로 판단하기 어려울 때는 "Chat about this"가 아니라 "잘 모르겠다"를 고르게 해요(위키 `notify.answer.two-questions` v2, `notify.answer.unsure-later`, T3 결정기록 5-12).

### 3-4. 답을 기록한 뒤

```
 ⎿ PostToolUse:mcp__notice__respond says:
   ✓ 기록했어요. 에이전트가 바뀐 결정 사항을 다시 읽었어요.

   확인할 변경이 1건 남았어요.

   ⟦ 2/2 ⟧
   [notify] 알림에는 이전 값, …
```

관계없다로 답하면 첫 줄이 `✓ 기록했어요.`만 나와요. 마지막 변경까지 답하면 `변경 2건을 모두 확인했어요. 이제 작업을 시작할게요.`가 나오고(10/15 문구) 작업을 시작해요.

### 3-5. 종류별 "변경" 줄

| 종류        | 모양                                                                                              |
| ----------- | ------------------------------------------------------------------------------------------------- |
| 단어를 바꿈 | `변경  40자 ⭢ **32자**` + 빈 줄. 일대일로 바뀌면 앞의 이전 텍스트(`40자`)는 흐린 글자(10/12 부건) |
| 단어를 지움 | `변경  "**근거,**" 삭제` + 빈 줄                                                                  |
| 단어를 넣음 | `변경  "**…**" 추가` + 빈 줄                                                                      |
| 크게 바뀜   | `변경  문장을 새로 썼어요` / `이전  …` + 빈 줄                                                    |
| 폐기        | `변경  결정 사항을 폐기했어요` / `이전  …` + 빈 줄                                                |
| 신규        | `변경  새로 생긴 결정 사항이에요` + 빈 줄                                                         |

## 5. 이렇게 정한 이유

### 5-1. 켤 때는 건수만, 상세는 작업을 시작할 때 (결정)

- 켤 때 알림은 작업 흐름을 막지 않고 예고만 해요. 변경 제목과 바꾼 사람 목록을 넣었던 시안은 부건이 빼기로 했어요.
- Claude Code는 사용자가 먼저 입력하기 전에는 말을 걸 수 없어요. 정민님의 10/9 시험(`docs/CLI-동작-시험.md`)과 이번 시안에서 똑같이 확인했어요. 그래서 답을 받는 시점은 첫 작업을 입력할 때예요.
- hooks 메시지는 키 입력을 받을 수 없어서, 켤 때 화면에 버튼을 두면 누를 수 없는 그림이 돼요.

### 5-2. 작업 전에 바로 답하기 (방식 2, 결정)

- 고르는 단계("지금 확인 / 작업 먼저")를 두면 매번 "작업 먼저"만 누르고 넘어갈 수 있어요.
- 알리기만 하고 작업을 이어 가면 답을 거의 받지 못해 "몰랐다" 수를 셀 수 없어요.

### 5-3. 상세 화면은 hooks가 직접 띄워요 (결정)

- 처음에는 MCP 서버가 화면 글을 만들고 Claude가 그대로 옮기게 했어요. 그런데 시안 세션 기록을 보니 Claude가 그 단계를 **건너뛰고 질문만 띄웠어요.** 정민님 시험에서도 두 번째 카드부터 Claude가 한두 문장으로 줄였어요.
- hooks는 입력할 때(`UserPromptSubmit`)와 도구를 쓴 뒤(`PostToolUse`)에도 화면에 글을 띄울 수 있어요. 시안에서 실제로 보이는 것을 확인했어요.

### 5-4. "관계없다" 이유는 보기 3개 (결정, 보기 문구는 제안)

- 위키 `notify.answer.unrelated-reason`이 이유를 받는 목적은 "이슈 연결과 적용 범위 중 무엇이 틀렸는지 알기"예요. 보기를 그 갈래대로 나눴어요.
  - 작업 범위가 아니에요 → 결정 사항의 적용 범위가 틀림
  - 연결이 잘못됐어요 → 이슈와 결정 사항의 연결이 틀림
  - 바뀐 부분은 안 쓰여요 → 둘 다 맞지만 이번 변경 내용만 상관없음
- 부건이 "최소 3개"로 정했어요.

### 5-5. 변경 요약 + 지금 값 (E 방식, 결정)

- 받는 사람에 디자이너가 섞여 있고 1분 안에 판단해야 해서, 바뀐 부분을 말로 먼저 보여 줘요.
- 두 줄 비교(이전/지금)는 긴 문장일 때 두 줄을 오가며 비교해야 해요. 요약은 그럴 필요가 없어요.
- 이름표 "변경 / 이전 / 지금"을 두 글자로 맞춰서, 아래 이유·이슈·출처와 한 덩어리로 보여요.

### 5-6. 바꾼 사람은 문장으로 (결정)

- `부건 · 오후 2:13`보다 `호윤님이 오후 6:00에 변경했어요.`가 누가 무엇을 했는지 바로 읽혀요.
- "수정"과 "변경"이 섞여 있어서 "변경"으로 맞췄어요.

### 5-7. 칩 대신 대괄호와 글자색 (결정)

- 영역, 출처, 폐기, PR에서 찾음을 모두 배경색 칩으로 했더니 색이 너무 많아 어수선했어요. 부건이 대괄호와 글자로 바꾸기로 했어요.
- 칩은 "몇 번째인지(1/2)" 하나만 남겼어요. 반전으로 만들어서 어느 테마에서도 대비가 생겨요.

### 5-8. 형광펜 강조 (결정 → 10/12 변경 줄은 굵게로 고침)

- 10/12: 부건이 변경 줄의 바뀐 부분에서 배경색을 지우고 굵게만 강조하기로 했어요. 아래는 처음 형광펜을 정한 이유예요. 굵게는 바로 아래 `지금` 줄(터미널 기본 글자색)보다 덜 튀어서 실제 화면에서 확인이 필요해요
- 노란 글자는 어두운 터미널에서는 잘 보이지만, 밝은 터미널(Orca의 Tango Light)에서는 탁한 올리브색이 돼서 가장 중요한 "바뀐 부분"이 가장 안 보였어요.
- 노란 배경 + 검정 글자는 서로 대비를 만들어서 터미널 배경이 희든 검든 보여요.

### 5-9. 테마를 추측하지 않아요 (결정)

- hooks는 터미널 배경색을 물어볼 수 없어요(키보드·화면에 직접 닿을 수 없음, 6장 테스트 C).
- 맥 화면 모드로 추측했더니, 맥은 라이트인데 터미널은 어두운 경우에 검정 글자를 칠해 버렸어요.
- 그래서 흰색·검정을 직접 고르지 않고, 터미널이 자기 테마에 맞춰 바꾸는 색(기본 글자색, 16색, 반전)만 써요.

### 5-10. 화살표 `⭢` (결정)

- `↳`은 개발 관례를 모르는 사람에게도 통했지만, 부건이 오른쪽 화살표 하나를 원했어요.
- `→`는 한국어 설정("애매한 폭 문자를 2칸으로")에서 2칸이 돼요(T2-본문 결정기록 4장 9번과 같은 이유). `⭢`는 어디서나 1칸이에요.

### 5-11. "지금" 줄은 빼요 (결정, 10/12)

- 부건이 "핵심은 제목에 다 들어가 있다"며 빼자고 했어요.
- 확인해 보니 지금까지 다룬 변경 9개(샘플 7개, SIL-64 예시, 데모 예시) 모두 값이 바뀔 때 제목도 함께 바뀌었고, 새 제목이 새 값의 핵심을 말해요. 지금 값이 더 주는 건 "공백 포함", "고른 변경부터 하나씩"처럼 세부 조건이에요.
- 경우별로 남는 것: 작게 바뀜은 제목 + 변경 줄, 신규는 제목이 곧 내용, 문장을 새로 씀은 제목(새 내용) + 이전 줄.
- 위험: 값만 고치고 제목을 그대로 두면 문장을 새로 쓴 변경의 새 내용이 안 보여요. "값이 바뀌면 제목도 고친다"는 전제를 경하님께 확인해요(경하-4).
- 위키 `notify.terminal.show-fields`와 착수 문서 T3 필수 항목(이전 값, 지금 값)과 달라요. 시안만 먼저 바꾸고 호윤님께 확인해요(호윤-15).
