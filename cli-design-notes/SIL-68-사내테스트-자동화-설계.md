# SIL-68 터미널 알림 · 사내 테스트 자동화 설계

- 작성: 2026-10-12 · 부건 (Claude와 대화하며 정리)
- 대상: 터미널 알림 시안 (`prototype/notify-prototype`)
- 목적: 진행자가 기록표와 초시계 없이, 명령 하나로 참가자 정보 입력 → 시안 진행 → 이해도·수고 설문 → 결과 저장까지 하게 해요
- 함께 볼 문서: [SIL-68-사내테스트-진행대본.md](SIL-68-사내테스트-진행대본.md) (알고 싶은 것, 진행자가 지킬 것)

---

## 1. 정한 것

| 항목           | 결정                                                                                                       |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| 방식           | 진행 스크립트 하나(`test_run.py`)가 Claude Code를 감싸요. 시안에는 시각을 남기는 줄과 테스트 모드만 더해요 |
| 예시 시안      | 변경 종류 3가지를 담은 테스트 데이터 하나(`changes-test.json`)를 모두에게 같이 써요                        |
| 이해도         | 변경 하나에 답을 끝낼 때마다 바로 물어요. 주관식 한 줄 → 객관식 "무엇이" → 객관식 "왜" 순서예요            |
| 이해도 묻기 전 | 빈 줄로 방금 본 상세를 화면 위로 밀어내요. 기억으로 답하게 해요                                            |
| 수고 설문      | Claude Code를 닫은 뒤 한 번만 물어요                                                                       |
| 결과           | 부건 컴퓨터의 `results/`에만 남기고 GitHub에는 올리지 않아요                                               |

## 2. 진행 순서

```
./test_run.py
 1. 진행자 입력   이름, 직군(개발/디자인/기타), 이 작업을 알았나(사일로/아님), 터미널 테마(어두움/밝음)
                  터미널 가로·세로 칸 수는 자동으로 적어요
 2. 준비          답 기록·시각 기록을 지우고 "참가자에게 넘겨 주세요" + 맡은 이슈 안내 한 줄
 3. Enter         Claude Code가 테스트 모드로 켜져요 (NOTICE_DATA=changes-test, NOTICE_TEST=1)
 4. 참가자 진행   알림 → 작업 입력 → 변경마다 [상세 → 관계 → 알았나/이유 → 기록 줄 → 이해도 3문항] × 3
                  다 답하면 원래 작업은 하지 않고 3초 뒤 Claude Code가 자동으로 닫혀요
                  (중간에 그만하려면 /exit)
 5. 수고 설문     터미널에서 바로: 쉬웠나 1~7, 다시 답할 것 같나 1~5, 시간 느낌, 헷갈린 말, 하고 싶은 말
 6. 저장·요약     results/에 저장하고 화면에 요약을 보여 줘요
```

시작 전 안내는 두 화면이에요. 문구는 `test_run.py`의 `HOST_GUIDE`, `PARTICIPANT_GUIDE`에 있어요.

- 진행자 안내: 설명하지 않기, 물으면 되묻기, 말한 것 적기 (진행 대본 5장)
- 참가자 안내 (24줄 한 화면): 상황(맡은 이슈 #6·#7), 진행 순서 5단계, 답하는 법(화살표·Enter, "Type something.", `/exit`), 소리 내어 말하기
- 답 이름(관계있다·몰랐다 등)과 도구가 무엇을 하는지는 안내에 넣지 않아요. 설명이 필요했다면 그 자체가 결과예요 (진행 대본 5장).

## 3. 예시 시안 3개 (`changes-test.json`)

| #   | 종류                | 결정 사항                 | 바뀐 내용                                          | 이슈 | 출처           | 관계 정답 |
| --- | ------------------- | ------------------------- | -------------------------------------------------- | ---- | -------------- | --------- |
| 1   | 숫자 하나가 바뀜    | `app.notify.title-length` | 공백 포함 40자 이하 → 32자 이하                    | #7   | AI 대화        | 관계있다  |
| 2   | 새로 생긴 결정 사항 | `notify.answer.note`      | (새로) 보기 대신 쓴 글은 답이 아니라 메모로 남긴다 | #6   | AI 대화        | 관계있다  |
| 3   | 일부러 관계없는 것  | `work.release.staged`     | 다른 팀 배포를 10/16 발표 뒤로 미룬다              | #6   | PR · AI가 찾음 | 관계없다  |

- 바꾼 사람은 부건·호윤·민수를 섞고, 참가자 본인은 아니게 해요.
- 변경마다 `quiz` 칸에 이해도 문제(보기 4개, 정답 번호)를 넣어요. 관계 정답도 `expected` 칸에 넣어요. 둘 다 화면에는 보이지 않아요.

## 4. 이해도 질문 흐름 (테스트 모드에서만)

1. 참가자가 알았나(또는 이유)까지 답하면 Claude가 `respond`로 기록해요.
2. 기록 뒤 hooks가 빈 줄(터미널 세로 칸 수만큼) + 기록 줄만 띄워요. 다음 상세는 아직 띄우지 않아요.
3. Claude가 시안용 MCP의 `get_quiz`로 문제를 받아 선택 화면 한 번에 3문항을 물어요.
   - 무엇이 무엇으로 바뀌었나요? (주관식: "Type something."에 한 줄. 선택 화면은 보기가 2개 이상 있어야 해서 "기억나지 않아요", "제대로 안 읽었어요"를 둬요)
   - 무엇이 바뀌었나요? (객관식 4개)
   - 왜 바뀌었나요? (객관식 4개)
4. Claude가 `save_quiz`로 기록하면 hooks가 다음 변경 상세를 띄워요. 마지막 변경이면 "테스트가 끝났어요" 문구를 띄우고 Claude를 멈춰요(원래 작업을 시작하지 않아요). `test_run.py`가 이걸 보고 3초 뒤 Claude Code를 닫고 수고 설문으로 넘어가요.
5. 참가자가 질문을 Esc로 닫으면 시안의 원래 규칙대로 남은 변경은 묻지 않아요. 닫은 것도 기록돼요.

테스트 모드가 아닐 때(`NOTICE_TEST` 없음)는 지금 시안과 똑같이 움직여요.

## 5. 자동으로 재는 시간

시안이 `.events.jsonl`에 초 단위 시각을 한 줄씩 남겨요.

| 사건                | 남기는 곳                      |
| ------------------- | ------------------------------ |
| 켤 때 알림          | SessionStart hooks             |
| 상세를 띄움         | UserPromptSubmit / PostToolUse |
| 답을 기록함         | MCP `respond`                  |
| 이해도를 기록함     | MCP `save_quiz`                |
| 닫은 뒤 한 줄       | UserPromptSubmit               |
| 다시 부름           | UserPromptSubmit               |
| Claude Code 시작·끝 | `test_run.py`                  |

여기서 계산해요: 변경마다 판단 시간(상세 → 답 기록), 이해도에 걸린 시간(답 기록 → 이해도 기록), 전체 시간(시작 → 끝), 닫은 횟수, 다시 불렀는지.

관계를 고른 순간과 알았나를 고른 순간은 나눠 잴 수 없어요. 두 답이 `respond` 한 번에 기록되기 때문이에요.

## 6. 결과 파일

- `results/20261012-1530-이름.json`: 참가자 정보, 터미널 크기, 사건 기록 전체, 답, 이해도, 수고 설문, 계산한 숫자
- `results/summary.csv`: 한 사람당 한 줄 (이름, 직군, 사일로, 테마, 전체 초, 변경당 평균 초, 관계 정답 수/3, "무엇이" 정답 수/3, "왜" 정답 수/3, 쉬웠나, 다시 답할 것 같나, 시간 느낌, 닫은 횟수)
- Claude Code가 끝난 직후 한 번, 설문 뒤 한 번 저장해요. 설문 중에 끊겨도 진행 기록은 남아요.
- `notify-prototype/.gitignore`에 `results/`, `answers.json`, `quiz.json`, `.flow.json`, `.events.jsonl`을 넣어 GitHub에 올라가지 않게 해요.

## 7. 확인할 것

- Claude Code가 hooks 글의 빈 줄을 그대로 보여 주는지. 줄이면 빈칸 한 개짜리 줄로 바꿔 봐요.
- 선택 화면 한 번에 3문항을 물을 때, 주관식 탭에서 "Type something."이 자연스럽게 보이는지.
- 이 확인은 부건님이 직접 한 번 돌려 보면서 해요. Claude는 hooks와 MCP를 직접 불러 보는 시험까지 해요.

## 8. 하지 않는 것

- 참가자별 실제 이슈로 데이터 만들기 (진행 대본 3-1). 모두 같은 예시 3개를 써요.
- 화면 녹화, 다른 팀 동의 받기 화면.
- `notice.py`의 컴퓨터 폴더 위치 고치기. 이번에는 부건 컴퓨터에서만 돌려요.
