## 2. A. 기본 흐름 (기대 결과 정해짐)

10/12 오후에 ①과 ②를 한 단계로 합치고, 충돌 화면과 ③을 hooks가 띄우게 바꿨어요(결정기록 2장, 5-6). 아래 기대 화면은 시안 `proto/screens.py`가 실제로 만든 글이에요.

### A1. 경우 1 · 끝까지 등록

- **입력:** `Windows 알림 창에서 잘리니까 알림 제목을 32자에서 자르게 고쳐 줘`
- **고를 것:** 예 → 등록하기

```
⎿ 부탁하신 작업이 기존 결정 사항과 충돌해요.
    작업  {알림 제목을 32자에서 자르기}

    구분    충돌하는 이유                           결정 사항 ID
    ──────  ──────────────────────────────────────  ──────────────────────────
    바뀜    40자 이하로 정한 길이를 32자 이하로     app.notify.title-length
            다시 정해요
    어긋남  결정 사항 제목(최대 40자)을 그대로      notify.….from-standard
            쓰면 32자에서 잘려요

☐ 결정 사항 등록
결정 사항도 바꾸는 작업인가요?   1. 예  2. 아니요

⎿ 결정 사항을 이렇게 등록할까요?

    [app] 앱 알림 제목은 32자 이하로 쓴다
      값    공백 포함 32자 이하
      이유  {Windows 알림 창에서 32자를 넘으면 제목 끝이 잘림}

      항상 적용  아니오

    ID   이슈                            담당자  근거 결정 사항
    ───  ──────────────────────────────  ──────  ─────────────────────────────
    #5   담당자에게 알리고 답 기록하기   민수    app.notify.title-length 외 1
    #7   앱 알림과 나에게 온 변경 화면   신지    app.notify.title-length 외 1

☐ 결정 사항 등록
등록할까요?   1. 등록하기  2. 수정하기  3. 취소하기

⎿ ✓ 결정 사항을 등록했어요.
    [app] 앱 알림 제목은 32자 이하로 쓴다  항상 적용 아니오
    연결된 이슈 2개의 담당자에게 확인할 변경을 보냈어요.

● 하던 작업을 이어갈게요.
  (src/notify-title.ts 수정)
```

- **확인할 점**
  - 충돌 화면이 코드를 고치기 **전에** 떠요.
  - **충돌 화면과 ③을 Claude가 글로 다시 쓰거나 요약하지 않아요.** 도구를 부른 바로 다음에 선택 화면이 떠요.
  - 첫 줄이 빨간 굵은 글자예요. 충돌이 표(구분 · 충돌하는 이유 · 결정 사항 ID)로 나오고, 이유는 한 문장이에요. 긴 ID는 `notify.….from-standard`처럼 줄여요.
  - ③에서 제목이 32자로 바뀌어 있고, 이유를 따로 묻지 않아요. 표에 #3(부건 본인)이 없어요.
  - 등록하기 설명이 `저장하고 연결된 이슈 담당자 2명에게 알려요`예요.
  - 끝나고 `MAX_TITLE_LENGTH = 32`, `saved.json`에 v2가 있어요.

### A2. 경우 1 · 아니요

- **입력:** A1과 같음 · **고를 것:** 아니요
- **기대:** 충돌 화면 → 아니요 → `● 등록하지 않았어요. 하던 작업을 이어갈게요.` → 코드만 32자로 고쳐요.
- **확인할 점:** ③이 뜨지 않아요. `saved.json`이 없어요. 코드는 고쳐져요.

### A3. 경우 2 · 직접 바꾸기 (묻지 않고 ③으로)

- **입력:** `앱 알림 제목 결정 사항을 32자로 바꿔 줘. Windows 알림 창에서 잘려.`
- **고를 것:** 등록하기
- **기대:** 충돌 화면의 첫 줄이 `요청하신 변경이 기존 결정 사항과 충돌해요.`, 둘째 줄이 `요청  {…}`예요. **선택 화면 없이** 바로 ③이 떠요. ③·④는 A1과 같아요.
- **확인할 점:** "결정 사항도 바꾸는 작업인가요?"를 묻지 않아요. ③의 질문이 `위 충돌 내역을 확인했나요? 이대로 등록할까요?`예요(충돌이 있어서, 10/13). A7처럼 충돌이 없으면 `등록할까요?`예요. 코드 파일을 고치지 않아요. ④ 뒤에 `하던 작업을 이어갈게요.` 대신 `등록을 마쳤어요.` 한 줄만 써요(하던 작업이 없어서). ④를 되풀이해 요약하지 않아요.

### A4. 충돌이 없는 작업 · T1이 뜨지 않음

- **입력:** `src/notify-title.ts에 함수 설명 주석 달아 줘`
- **기대:** 충돌 화면이 뜨지 않고 주석만 달아요.
- **확인할 점:** 결정 사항 값과 다르지 않은 작업에서 T1이 끼어들지 않아요. (10/12 전의 A4 "②에서 아니요"는 경우 2에서 묻지 않게 되면서 없어졌어요.)

### A5. 수정하기 · 항상 적용 바꾸기

- **입력:** A3과 같음 · **고를 것:** 수정하기 → `항상 적용으로 바꿔 줘` → 다시 뜬 ③에서 등록하기
- **기대:** `● 무엇을 고칠까요?` → 입력 → ③이 처음부터 다시 떠요. 항상 적용 줄은 `항상 적용  예`예요. ④는 `항상 적용 예`예요.
- **확인할 점:** 다시 뜬 ③에서 다른 줄(제목·값·이유·표)이 그대로예요.

### A6. 취소하기

- **입력:** A3과 같음 · **고를 것:** 취소하기
- **기대:** `● 등록하지 않았어요. 하던 작업을 이어갈게요.`
- **확인할 점:** `saved.json`이 없어요.

### A7. 새 결정 사항 · 충돌 없음 · 알림 0명

- **입력:** `앱 알림 본문은 2줄 이하로 쓰기로 결정 사항 만들어 줘. 운영체제가 3줄부터 잘라.`
- **고를 것:** 등록하기

```
⎿ 관련 결정 사항을 찾아봤어요. 충돌하는 결정 사항이 없어요.
    요청  {앱 알림 본문을 2줄 이하로 쓰는 결정 사항 만들기}

⎿ 결정 사항을 이렇게 등록할까요?

    [app] {앱 알림 본문은 2줄 이하로 쓴다}                          새 결정 사항
      값    {운영체제 알림 본문은 2줄 이하로 쓴다}
      이유  {운영체제 알림 창이 3줄부터 잘라요}

      항상 적용  아니오

    연결된 이슈가 없어서 알림을 받는 사람은 없어요.

☐ 결정 사항 등록
등록할까요?   1. 등록하기 (저장해요. 알림을 받는 사람은 없어요)  2. 수정하기  3. 취소하기

⎿ ✓ 결정 사항을 등록했어요.
    [app] {앱 알림 본문은 2줄 이하로 쓴다}  새 결정 사항 · 항상 적용 아니오
    연결된 이슈가 없어서 알림을 받는 사람은 없어요.

● 등록을 마쳤어요.
```

- **확인할 점:** "알림"이 같은 낱말이라 `app.notify.title-length`가 검색에 걸려도 충돌로 보지 않아요. 새 ID가 `영역.주제.규칙` 형식이에요(예: `app.notify.body-lines`).

### A8. 사람이 한 말에 이유가 없음 → 직접 입력

- **입력:** `앱 알림 본문은 2줄 이하로 쓰기로 결정 사항 만들어 줘` (이유 없음)
- **고를 것:** 이유 질문에 `윈도우랑 맥 둘 다 알림 센터에서 본문이 3줄부터 말줄임표로 바뀌는데 그러면 이전 값이랑 지금 값을 같이 못 봐서 판단이 안 됨` 입력 → 등록하기
- **기대:** 충돌 없음 두 줄 → `● 왜 바꾸는지 알려 주세요. 적어 주시면 정리해서 넣을게요.` → 입력 → 바로 ③
- **확인할 점:** 작업 내용이나 다른 결정 사항으로 이유를 지어내지 않고 먼저 물어요. ③의 이유가 한 문장(120자 이하)으로 정리되고, 길면 띄어쓰기 단위로 줄이 바뀌어 다음 줄이 값 칸에 맞춰져요. 정리한 이유를 다시 확인하는 질문이 없어요.

## 3. B. 충돌 구분

10/12에 충돌 구분을 바뀜·어긋남 두 가지로 줄였어요(결정기록 4-3). 바뀜과 어긋남은 A1에서 확인해요. 남은 것은 B3 하나예요.

## 5. 결과 기록

10/12 저녁에 B 방식으로 A1~A8을 다시 돌렸어요. `claude -p`로 자동으로 돌려서 선택 화면이 뜨지 않아요. Claude가 선택지를 글로 묻고, 그 답을 다음 메시지로 보냈어요. 그래서 선택 화면 모양과 등록 뒤 마지막 말은 터미널에서 직접 다시 봐야 해요(표의 "직접 확인").

| 케이스 | 날짜  | 결과 | 메모                                                                                                                                                          |
