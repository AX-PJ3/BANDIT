## 1. 먼저 알아 둘 것

| 항목 | 내용 |
|---|---|
| 이 DB의 버전 번호 | **DB는 전부 v1부터 시작**해요. 위키에 `버전: 2`라고 적힌 `app.notify.title-length`도 DB에서는 v1이에요. 처음 저장하면 v2가 돼요 |
| 연결한 결정 사항 | DB에 이미 있는 것만 썼어요. 결정 사항 104개 상태에서 그대로 돼요 (위키에만 있는 8개는 필요 없어요) |
| 시험은 되돌릴 수 없어요 | 저장한 버전은 지워지지 않아요. 시험용 DB에서만 해요 |
| 이름 | 사람을 바꿀 때마다 `claude mcp remove haribo --scope user` 뒤 `pnpm mcp:register --local --user <이름>`으로 다시 등록하고 Claude Code를 새로 켜요 |

## 2. 샘플 이슈 7개

| 이슈 | 담당 | 상태 | 연결한 결정 사항 | 맡는 역할 |
|---|---|---|---|---|
| `#1` | 정민 | 진행 중 | `wiki.read.index-first` | 결정 사항을 바꾸는 사람 |
| `#2` | 경하 | 진행 중 | `detect.change.ai-mark` | 연결이 다르면 알림이 안 오는지 |
| `#3` | 부건 | 진행 중 | `notify.terminal.one-change`, `app.notify.title-length` | 받는 사람 |
| `#4` | **없음** | 진행 중 | `app.notify.title-length` | 담당 없음 |
| `#5` | 민수 | 진행 중 | `app.notify.title-length`, `notify.answer.two-questions` | 받는 사람 |

시험 대상은 모두 `app.notify.title-length`예요. 지금 값은 "운영체제 알림 창에 뜨는 제목은 공백 포함 40자 이하로 쓴다"(DB v1)예요.

## 3. 시험 순서 (이 순서대로)

한 번 저장하면 되돌릴 수 없어서 **순서를 지켜 한 번만** 돌려요.

| 단계 | 이름 | 하는 일 | 이렇게 보여야 해요 | 확인하는 케이스 |
|---|---|---|---|---|
| A | 정민 | `save_standard`로 `app.notify.title-length`의 값을 바꿔 저장 (baseVersion 1 → v2) | 부건 2건(`#3`, `#6`), 민수 1건(`#5`), 신지 1건(`#7`). **정민·경하는 0건, `#4`는 알릴 사람이 없어서 0건** | 기본 알림, 연결 안 된 사람 제외, 담당 없음 제외, 완료된 이슈에도 알림, 한 사람에게 이슈 2개 |
| B | 민수 | `list_pending` | 1건. 이전 값(40자)과 새 값, 이유, 바꾼 사람(정민), 내 이슈(`#5`)가 같이 와요. `previousAnswer`는 없어요 | 목록 한 번에 보기 |
| C | 민수 | `respond` 관계있다 + 몰랐다 | 기록됨. `list_pending` 다시 부르면 0건 | 관계있다 + 몰랐다 |
| D | 신지 | `respond` 관계없다 + 이유 한 줄 | 기록됨 (이유 포함) | 관계없다 + 이유 |
| E | 정민 | 값을 한 번 더 바꿔 저장 (v3) | 부건의 v2 건 2개는 "대체됨"으로 닫히고 v3 건이 새로 생겨요. 민수·신지도 답한 뒤에 바뀌었으니 v3 건이 새로 생겨요 | 답하기 전에 또 바뀜(대체됨), 답한 뒤에 또 바뀜(다시 알림) |
| F | 정민 | `revert`로 v1로 되돌리기 (v4) | **부건**: 마지막으로 본 값(v1)과 같아서 열린 v3 건이 "자동 닫힘", 새 건 없음. **민수·신지**: 마지막으로 본 값은 자기가 답한 v2라서, 열려 있던 v3 건은 "대체됨"으로 닫히고 되돌림 v4 건이 새로 생겨요 (되돌림 표시, `previousAnswer`) | 되돌림 자동 닫힘, 답한 사람은 열린 v3 대체됨 + 되돌림 건 + "지난번 변경을 반영하셨다면 다시 고쳐야 해요" |
| G | 부건 | 값을 바꿔 저장 (v5) | **부건의 `#3`, `#6`은 안 생겨요**(바꾼 본인). 민수·신지 건만 생겨요 | 바꾼 사람 본인 제외 |

- **E~F는 누가 답했는지에 따라 결과가 달라요.** 그래서 B~D에서 민수·신지만 답하고, 부건은 일부러 답하지 않아요.
- **G는 마지막에** 해요. 앞 단계는 정민 이름으로 해야 부건이 받는 쪽이에요.

## 4. 이 샘플로 확인 못 하는 것

| 케이스 | 이유 |
|---|---|
| 새 결정 사항(v1)의 "이전 값 없음" 카드 | 연결은 결정 사항이 있어야 걸 수 있어서, v1은 알림이 생길 수 없어요 |
| 담당자 변경 시 대기 건이 옮겨지는 것 | 위키 도구 5개에 이슈 저장 도구가 없어요(코드로만 확인) |
| 터미널을 켤 때 자동으로 알림 | 훅 연결이 아직 없어요. `list_pending`을 직접 불러야 해요 |
| "완료된 이슈 다시 열까요?" 질문 | 에이전트가 하는 일이라 안내문에 따라 달라요. 서버는 이슈 상태를 바꾸지 않아요 |

## 5. 막혔을 때

| 증상 | 확인 |
|---|---|
| A 뒤에 `list_pending`이 빈 목록 | 이슈 연결이 DB에 들어갔는지, 담당자 이름이 등록한 `--user`와 같은지, 값을 **실제로 바꿔** 저장했는지 |
| `save_standard`가 버전 충돌 | `get_standard`로 지금 버전을 보고 그 값을 baseVersion으로 넣어요 |
| 위키 가져오기에서 `NOT_FOUND` | 위키에 없거나 폐기된 ID를 연결한 거예요 |
