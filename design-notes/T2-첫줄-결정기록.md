# T2 첫 줄(상태 줄) 결정 기록

- 작성: 2026-10-10 · 부건 (Claude와 대화하며 정리) · 같은 날 고침 1회 (아래 "고친 기록")
- 관련 이슈: SIL-68 [디자인] 터미널 알림과 답하기 화면
- 대상 화면: T2 「나에게 온 변경 요약」의 맨 윗줄. Claude Code를 켰을 때 가장 먼저 보이는 줄
- 표기: **결정**은 부건이 정한 것, **제안**은 Claude가 낸 의견, **미정**은 아직 정하지 않은 것
- 이어지는 문서: [T2-본문-결정기록.md](T2-본문-결정기록.md)

## 1. 결정한 모양

```
● [app] SIL-67 관련 기준 변경이 1건 있어요.
● [app, goal] SIL-67 관련 기준 변경이 총 2건 있어요.
● [goal, wiki, detect, …] SIL-67 외 3개 관련 기준 변경이 총 12건 있어요.
```

| 경우                                                                                   | 너비 (한글 2칸, 기호 2칸 기준) |
| -------------------------------------------------------------------------------------- | ------------------------------ |
| 1건, 영역 1개, 이슈 1개                                                                | 44칸                           |
| 가장 긴 경우: 가장 긴 영역 3개(detect, notify, wiki) + `…` + `SIL-1234 외 2개` + 120건 | 79칸                           |

여러 이슈를 `외 N개`로 줄이는 규칙은 **미정**이에요(6장). 이 규칙이 없으면 가장 긴 경우가 86칸으로 넘쳐요.

## 2. 작성 규칙

| 항목      | 규칙                                                                                                                                                   |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 모양      | `● [영역] 이슈코드 관련 기준 변경이 (총) N건 있어요.`                                                                                                  |
| 문체      | 문장형 해요체                                                                                                                                          |
| 영역 이름 | 위키 원본 이름 그대로: `goal` `wiki` `detect` `notify` `app` `data` `copy` `work`. 기준 ID의 맨 앞 단어로 정해져요 (`app.notify.title-length` → `app`) |
| 대괄호    | 영역을 대괄호로 감싸요                                                                                                                                 |
| 여러 영역 | 대괄호 하나 안에 쉼표로 나열해요: `[app, goal]`                                                                                                        |
| 4개 이상  | 3개까지 쓰고 그 뒤는 `…`: `[goal, wiki, detect, …]`                                                                                                    |
| 영역 순서 | 위키 목차 순서 (goal → wiki → detect → notify → app → data → copy → work)                                                                              |
| 이슈      | 이슈 코드를 그대로 써요 (`SIL-67`). 조사 없이 "관련"을 붙여요                                                                                          |
| "총"      | 2건 이상일 때만 붙여요                                                                                                                                 |
| 너비      | 최소 80칸에서 잘리지 않고, 넓어져도 모양이 그대로예요                                                                                                  |

## 3. 이렇게 정한 이유

### 3-1. 첫 줄은 상태 줄이에요 (결정)

- 읽을 부담을 줄이려고, 첫 줄은 지금 상태만 짧게 말해요. 자세한 내용은 아래 줄로 내려요.
- 첫 줄에서 알려야 할 것은 두 가지예요. **어떤 영역의 기준이 바뀌었는지**, 그리고 **어느 이슈와 관련됐는지**예요.

### 3-2. "확인 필요" 같은 할 일 표현을 넣지 않아요 (결정)

- 이 화면 뒤에 사용자가 하는 일은 답하기 하나뿐이에요(T3 관련 판단, T4 알았나).
- T2에 이미 "지금 답할까요?"라는 질문이 있어서, 첫 줄에서 할 일을 말할 필요가 없어요.

### 3-3. 영역을 맨 앞에 둬요 (결정)

- 사람들은 화면을 훑을 때 줄의 앞부분, 특히 **처음 두 단어**를 가장 많이 봐요. 핵심어를 앞에 두라는 연구가 있어요 (Nielsen Norman Group 시선 추적 연구 인용 자료).
- 한 번에 머릿속에 붙잡는 양은 **약 4덩어리**예요 (Cowan의 작업 기억 연구). 할 일 표현을 빼서 덩어리 수를 줄였어요.

### 3-4. 대괄호를 써요 (결정)

- 영역 이름을 본문과 구분되는 이름표로 보이게 해요. Primer CLI 가이드도 라벨을 괄호로 묶어요.
- 여러 영역을 대괄호 하나에 묶으면 따로 쓸 때보다 짧고, 하나의 이름표로 읽혀요.

### 3-5. 영역 이름은 원본 그대로 (결정)

- 데이터 항목 목록 v2에는 "영역" 칸이 없어요. 기준 ID 맨 앞 단어를 그대로 쓰면 새 이름을 만들고 관리할 필요가 없어요.

### 3-6. "내 이슈" 대신 이슈 코드를 써요 (결정)

- 어느 이슈인지 첫 줄에서 바로 알 수 있어요.
- 이슈 제목은 T2에서 빼고 T3에서 보여 줘요. 착수 안내 기준으로 T2의 필수 항목은 이슈 번호까지예요. 이슈 제목은 T3의 필수 항목이에요.
- 이슈 코드에 커서를 올려 제목을 보여 주는 방법도 검토했지만, 터미널에는 마우스를 올렸을 때 원하는 글을 띄우는 기능이 없어요. 링크를 걸면 일부 터미널(iTerm2, VS Code, Orca)에서 링크 주소만 보여요. macOS 기본 터미널은 링크가 안 돼요.

### 3-7. "관련"을 조사 없이 써요 (결정)

- 표준국어대사전 뜻풀이
  - **관련:** 둘 이상의 사람, 사물, 현상 따위가 서로 관계를 맺어 **매여 있음**. 또는 그 관계.
  - **관련되다:** 둘 이상의 사람, 사물, 현상 따위가 서로 **얽혀서** 가까운 관계에 있다.
  - **관계:** 둘 이상의 사람, 사물, 현상 따위가 서로 관련을 맺거나 관련이 있음. 또는 그런 관련.
- "관련"은 이어져 있다는 성격이 뜻풀이에 직접 들어가 있어요. 이 도구는 이슈와 기준을 연결표로 이어 둔 것을 보고 알리니까, 그 사실을 정확하게 말해요.
- 이슈 코드 뒤에 조사를 붙이면 숫자를 읽는 소리에 따라 "과/와"가 바뀌어요(SIL-67과, SIL-69와). "SIL-67 관련"은 조사가 없어서 이 문제가 없어요.

### 3-8. 영역은 3개까지만 (결정)

- 쉼표로 계속 나열하면 영역이 많을 때 80칸을 넘어요.

### 3-9. 위키 목차 순서로 (결정, 고침)

- 처음에는 "바뀐 지 오래된 순"으로 정했어요. 시간 순서가 이해하기 쉬워서예요.
- 그런데 SIL-64처럼 여러 기준이 한 PR로 한꺼번에 바뀌면 바뀐 시각이 모두 같아서 순서를 정할 수 없었어요.
- 그래서 위키 목차 순서로 바꿨어요. 늘 같은 순서라 예측하기 쉬워요.

## 4. 버린 시안과 이유

| 순서 | 시안                                                                                          | 버린 이유                                                                                                                                                                         |
| ---- | --------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | `● 작업을 시작하기 전에 확인할 변경이 2개 있어요.` (예전 Spec의 터미널 예시를 따른 초기 목업) | 어떤 영역이 바뀌었는지와 나와의 관계를 말해 주지 않아요                                                                                                                           |
| 2    | `● 확인할 변경 1개`                                                                           | 영역 정보가 없어요                                                                                                                                                                |
| 3    | `● 확인할 변경 1개 · 내 이슈 #5`                                                              | 영역 정보가 없어요                                                                                                                                                                |
| 4    | `● 확인할 변경 1개 · 앱 알림 제목은 32자 이하로 쓴다`                                         | 영역 정보가 없고, 제목이 들어가면 첫 줄이 길어져요                                                                                                                                |
| 5    | **B안:** `● 내 이슈 #5 관련 · [앱 화면] 기준 변경 확인 필요`                                  | 앞 두 단어가 영역이 아니에요. 할 일 표현(확인 필요)이 필요 없어요                                                                                                                 |
| 6    | **C안:** `● 확인 필요 · 내 이슈 #5에 걸린 [앱 화면] 기준 변경`                                | 할 일이 확인 하나뿐이라 "확인 필요"를 앞에 둘 이유가 없어요. 무엇이 바뀌었는지가 맨 뒤에 나와요                                                                                   |
| 7    | **A안:** `● [앱 화면] 기준 변경 · 내 이슈 #5 확인 필요`                                       | 방향(영역 먼저)은 채택했어요. 다만 "확인 필요"를 빼고, 명사형에서 문장형으로 바꿨어요                                                                                             |
| 8    | 영역 한글 이름: `[앱 화면]`, `[바뀐 기준 찾기]`                                               | 화면용 한글 이름을 새로 정해야 하고, "바뀐 기준 찾기 기준 변경"처럼 말이 겹쳐요                                                                                                   |
| 9    | A안 변형 A1 `● [app] 기준 변경 · 내 이슈 #5` / A3 `● 기준 변경 [app] · 내 이슈 #5`            | 문장형 시안(10번)으로 넘어가면서 정리했어요                                                                                                                                       |
| 10   | `[app] 알아둬야 할 기준 변경이 1건 있어요.`                                                   | "알아둬야 할"은 도구가 먼저 "당신과 관계있다"고 말하는 셈이에요. 사용자가 T3에서 따라 고르기 쉬워서, 핵심 지표(관계있다·몰랐다)가 사람의 판단이 아니게 될 수 있어요 (Claude 지적) |
| 11   | `[app], [goal] …` (대괄호 따로)                                                               | 대괄호 하나로 묶는 쪽이 짧고 하나의 이름표로 읽혀요                                                                                                                               |
| 12   | `내 이슈와 연결된 …` (Claude 제안)                                                            | 부건이 "관련"을 골랐어요                                                                                                                                                          |
| 13   | `내 이슈와 관련 있는 …`                                                                       | "관련된"으로 바꿨어요. 이어져 있는 상태를 더 정확히 말하고, 3칸 짧아요                                                                                                            |
| 14   | `내 이슈와 관련된 …`                                                                          | "내 이슈" 대신 이슈 코드를 쓰기로 했어요 (3-6)                                                                                                                                    |
| 15   | `SIL-67과 관련된 …`                                                                           | 이슈 코드 뒤 조사(과/와)가 숫자 소리에 따라 바뀌어요 (3-7)                                                                                                                        |
| 16   | 영역 순서 "바뀐 지 오래된 순"                                                                 | 한꺼번에 바뀌면 시각이 같아서 순서를 정할 수 없어요 (3-9)                                                                                                                         |

## 5. 함께 정한 것: 0건일 때

| 상황                               | 화면                      | 상태                                                             |
| ---------------------------------- | ------------------------- | ---------------------------------------------------------------- |
| Claude Code를 켤 때 자동 실행, 0건 | 아무것도 보여 주지 않아요 | 착수 안내를 따름                                                 |
| 명령어를 직접 호출, 0건            | 상태 한 줄로 답해요       | **결정**. 직접 불렀는데 반응이 없으면 고장으로 보이기 때문이에요 |

직접 호출할 때 쓸 문구 후보는 `✓ 나에게 온 변경을 모두 확인했어요.`예요 (**미정**).

- "모든 기준이 최신이에요"는 쓰지 않아요. 0건은 "내 이슈와 이어진 변경 중 답할 게 없다"는 뜻이라, 다른 기준이 바뀌었을 수 있어요.
- 직접 호출하는 명령어의 이름과 형태는 정해지지 않았어요. 예전 Spec에는 `brief`로만 나와요.

## 6. 남은 것

| 항목                          | 상태      | 메모                                                                                                                                                                        |
| ----------------------------- | --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 이슈가 여러 개일 때           | 미정      | 쉼표로 나열하면 최대 86칸으로 넘쳐요. `SIL-1234 외 2개`처럼 1개만 쓰고 개수로 줄이면 79칸이에요 (Claude 제안)                                                               |
| 이슈 번호 모양                | 미정      | 위키 `data.issue.linear-id`는 `SIL-12`, 착수 안내는 `#5`예요. 지금 기록은 위키를 따랐어요                                                                                   |
| T3 질문과 첫 줄이 겹침        | 미정      | 첫 줄에서 "관련"이라고 한 뒤 T3에서 "관련이 있나요?"라고 물으면 어색해요. 판단을 묻는 질문(예: "이 변경이 내 작업에 영향을 주나요?")으로 나누는 방법이 있어요 (Claude 제안) |
| 답 선택지 "관계있다/관계없다" | 보류      | 위키 `copy.term.related`(v1)에 정해져 있어요. "관련"으로 바꾸면 위키 기준을 바꾸는 일이에요                                                                                 |
| "기준"이라는 말               | 미정      | 위키 `copy.term.standard`는 "기준", 착수 안내와 SIL-69는 "결정 사항"이에요. 신지님과 맞춰요                                                                                 |
| "건"과 "개"                   | 미정      | 신지님 앱과 단위를 맞춰요                                                                                                                                                   |
| 맨 앞 기호 `●`의 폭           | 확인 필요 | 한국어 터미널 설정에 따라 1칸 또는 2칸이에요. 위 너비는 2칸으로 계산했어요                                                                                                  |
