# T3 질문과 답 결정 기록 (관계 질문 · 알았나 · 기록 줄 · 닫고 넘어갈 때)

- 작성: 2026-10-11 · 부건 (Claude와 대화하며 정리)
- 관련 이슈: SIL-68 [디자인] 터미널 알림과 답하기 화면
- 대상 화면: 변경 상세 바로 아래에 뜨는 질문부터 답을 기록한 뒤까지. 착수 문서의 T3 질문, T4, T5에 해당해요. 상세 화면 자체는 다루지 않았어요(그대로 둠)
- 표기: **결정**은 부건이 정한 것, **제안**은 Claude가 낸 의견, **미정**은 아직 정하지 않은 것. 착수 문서·위키에 없는 흐름은 **새 제안**이라고 따로 적었어요
- 앞 문서: [터미널-알림-흐름-결정기록.md](터미널-알림-흐름-결정기록.md) (3-3 질문, 3-4 기록 뒤, 9장 남은 것에서 이어져요)
- 단계: **시안 단계**예요. hooks를 직접 돌려 확인했고, 실제 Claude Code 스크린샷 확인은 남았어요(6장)

## 1. 이 화면이 하려는 일 (의도)

| 의도                               | 어떻게 지키나                                                                                       |
| ---------------------------------- | --------------------------------------------------------------------------------------------------- |
| **지표를 바로 셀 수 있다**         | 관계·알았나는 보기 중 하나만 기록해요. 직접 쓴 글은 답이 아니라 메모로 따로 남겨요                  |
| **어느 이슈에 답하는지 안다**      | 같은 변경이 이슈 두 개에 걸리면 같은 화면이 두 번 떠요. 선택 화면 맨 위 이름표에 이슈 코드를 넣어요 |
| **"몰랐다"가 줄어들지 않는다**     | 두 번째 이슈에서 "방금 봤으니 알았다"로 답하지 않게, 알았나의 기준 시점을 "오늘 알림"으로 적어요    |
| **내가 한 답이 보인다**            | 기록 줄에 이슈와 고른 답을 함께 보여 줘요 (착수 문서 T5 필수 항목)                                  |
| **급한 작업을 막지 않는다**        | 질문을 닫고 넘어가면 작업은 진행하고, 작업마다 한 줄로 알리면서 다시 답하는 방법을 알려 줘요        |
| **사람의 판단을 끌고 가지 않는다** | 추천 표시도, 앞에서 한 답도 보여 주지 않아요 (앞 문서 1장과 같아요)                                 |

## 2. 결정한 흐름

```
① 작업을 입력함 → 변경 상세 (앞 문서 그대로)
② 관계 질문      → 관계있다 → 알았나 질문
                 → 관계없다 → 이유 질문 (보기 3개 + 직접 입력)
   · 관계·알았나에 직접 글을 쓰면 기록하지 않고 같은 질문을 다시 물음. 쓴 글은 메모로
③ 기록 줄 "✓ 기록했어요  이슈 · 답"  → 다음 변경 상세, 또는 마무리 한 줄
④ 질문을 닫고 넘어가면
   → 이번 세션에서는 작업마다 한 줄 알림만 띄우고 작업을 진행함
   → "결정 사항 확인"만 입력하면 상세와 질문을 다시 띄움
   → Claude Code를 다시 켜면 처음처럼 물음
```

- **결정**: 완료된 이슈라도 "다시 열까요?"는 묻지 않아요. 착수 문서("완료된 이슈 다시 열기는 하지 않는다")와 SIL-64(`notify.answer.reopen-done` 폐기 예정)를 따라요. 위키 파일은 이번에 고치지 않았어요(9장 질문 목록).
- **결정**: 같은 변경이 이슈 여러 개에 걸려도 이슈마다 따로 보여 주고 따로 답해요(착수 문서). 두 번째 화면도 상세를 전부 다시 보여 줘요.
- **결정, 새 제안**: ④ 닫고 넘어갈 때의 흐름과 "결정 사항 확인"은 착수 문서·위키에 없어요. 민수님 확인이 필요해요.

## 3. 결정한 모양

`«»`는 형광펜, `⟦⟧`는 반전, `**`는 굵게, `‹›`는 노란 굵은 글자예요. 예시는 앞 문서와 같은 SIL-64 변경이고, 이어진 이슈는 SIL-34(완료)와 SIL-35예요.

### 3-1. 관계 질문 (Claude Code 선택 화면)

```
⟦ SIL-34 ⟧
이 변경이 내 이슈와 관계가 있나요?
❯ 1. 관계있다
     내 이슈 결과물이 이 변경에 맞춰 바뀌어야 해요
  2. 관계없다
     내 이슈와는 상관없는 변경이에요
  3. Type something.
  Chat about this
```

선택 화면의 모양은 Claude Code가 정해요. 우리가 정하는 건 이름표(이슈 코드), 질문, 보기, 설명 글이에요.

### 3-2. 알았나 질문 (관계있다일 때)

| 보기   | 설명                                |
| ------ | ----------------------------------- |
| 알았다 | 오늘 알림을 보기 전에 알고 있었어요 |
| 몰랐다 | 오늘 알림으로 처음 알았어요         |

이유 질문(관계없다일 때)은 앞 문서 3-3 그대로예요.

### 3-3. 기록한 뒤

```
✓ 기록했어요  SIL-34 · 관계있다 · 몰랐다
  다음 작업부터 바뀐 결정 사항을 따라요.

확인할 변경이 1건 남았어요.
(다음 변경 상세)
```

| 경우                           | 모양                                                                                                        |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| 관계없다                       | `✓ 기록했어요  SIL-35 · 관계없다 · 내 작업 범위가 아니에요` (둘째 줄 없음)                                  |
| 직접 쓴 긴 이유                | `✓ 기록했어요  SIL-34 · 관계없다 · 이 기준은 v0 시안에만 쓰였고 지금 맡은…`                                 |
| 마지막 변경                    | 기록 줄 + 빈 줄 + `확인할 변경 2건을 모두 답했어요. 이제 작업을 시작할게요.`                                |
| 1건만 답함                     | `확인할 변경을 모두 답했어요. …` (건수를 빼요)                                                              |
| "결정 사항 확인"으로 다시 부름 | 마지막 줄에서 `이제 작업을 시작할게요.`를 빼요. 상세 맨 위도 `작업 전에`를 빼고 `확인할 변경이 N건 있어요.` |

### 3-4. 닫고 넘어간 뒤

```
> 버튼 색 바꿔 줘
 ⎿ UserPromptSubmit says:
   ● 확인할 변경 ‹2›건 · **"결정 사항 확인"**을 입력하면 변경 내역을 볼 수 있어요.
(Claude가 원래 작업을 진행)
```

| 입력                                                  | 반응                                               |
| ----------------------------------------------------- | -------------------------------------------------- |
| `결정 사항 확인` (앞뒤 빈칸, 끝의 `.` `!` `?`는 무시) | 상세와 질문을 다시 띄워요                          |
| `변경 확인`, `결정 사항 확인해 줘`                    | 반응하지 않아요. 위 한 줄만 뜨고 작업으로 넘어가요 |
| 답할 게 없을 때 `결정 사항 확인`                      | `✓ 확인할 변경이 없어요.`                          |

## 4. 작성 규칙

| 항목                     | 규칙                                                                                                                                                                                    |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 선택 화면 이름표         | 그 변경의 이슈 코드: `SIL-34`. 세 질문 모두 같아요                                                                                                                                      |
| 질문·보기                | 앞 문서 3-3 그대로. 알았나 설명만 "오늘 알림" 기준으로 바꿨어요                                                                                                                         |
| 추천 표시                | 붙이지 않아요                                                                                                                                                                           |
| 관계·알았나에 직접 쓴 글 | 답으로 기록하지 않아요. 글이 질문이면 Claude가 한두 문장으로만 답하고 같은 질문을 다시 물어요. 쓴 글은 메모(`note`)로 함께 저장해요                                                     |
| 이유에 직접 쓴 글        | 그대로 이유로 기록해요 (100자 이하)                                                                                                                                                     |
| 기록 줄                  | `✓ 기록했어요` + 빈칸 2개 + `이슈 · 관계 · 알았나(또는 이유)`. ✓는 초록, 답 부분은 터미널 기본 글자색. 넘치면 끝을 `…`                                                                  |
| 기록 줄 둘째 줄          | 관계있다일 때만 `다음 작업부터 바뀐 결정 사항을 따라요.` 2칸 들여 쓰기, 기본 회색. 위키 `notify.answer.next-run-context`("다음 실행부터")에 맞춘 문구예요(10/12 고침, 5-10)             |
| 용어                     | 위키 항목은 **결정 사항**, 답할 항목은 **확인할 변경** (10/12, 5-11). 위키 `copy.term.standard`("기준")와 달라요                                                                        |
| 닫고 넘어간 뒤 한 줄     | `● 확인할 변경 N건 · "결정 사항 확인"을 입력하면 변경 내역을 볼 수 있어요.` 켤 때 알림 첫 줄과 같은 모양(터미널 기본 글자색, 숫자만 노란 굵은 글자). `"결정 사항 확인"`은 따옴표째 굵게 |
| 건수 숫자                | 숫자만 노란 굵은 글자(16색의 노랑 33 + 굵게), "건"은 빼요. 켤 때 알림도 같아요. 시안에서는 `NOTICE_COUNT_COLOR`로 바꿔 볼 수 있어요                                                     |
| 다시 부르는 말           | `결정 사항 확인`. 입력 전체가 같을 때만 반응해요                                                                                                                                        |
| 닫았는지 알아보기        | 이번 세션에서 질문을 띄웠는데 답하지 않은 변경이 남아 있으면 닫고 넘어간 것으로 봐요                                                                                                    |
| 너비                     | 76칸. 가장 긴 줄은 상세의 지금 값 75칸, 이번에 새로 만든 줄 중에서는 긴 이유가 들어간 기록 줄 73칸이에요                                                                                |
| 세로                     | Claude Code 머리줄 포함 15줄 안. 기록 뒤 화면 14줄, 문장을 새로 쓴 변경 15줄(빈 줄 2개를 뺌, 8장 21번)                                                                                  |

## 5. 이렇게 정한 이유

### 5-1. 다시 열기는 묻지 않아요 (결정)

- 세 문서가 서로 달랐어요. 위키(10/8 첫 등록)는 "묻는다", 착수 문서(10/9)는 "이번에 하지 않는다", SIL-64(10/11 마지막 수정)는 "폐기한다"예요. 셋 다 호윤님이 썼고, 가장 최근 문서인 SIL-64와 착수 문서가 같은 방향이에요.
- SIL-64가 아직 시작 전이라 위키 파일에는 예전 내용이 남아 있어요. 위키를 고치지 않고 질문 목록에 남겼어요.

### 5-2. 이름표에 이슈 코드 (결정)

- 같은 변경이 SIL-34와 SIL-35에 걸리면 상세 화면이 이슈 줄만 다르게 두 번 떠요. 질문 바로 위에서 어느 이슈에 답하는지 보여야 헷갈리지 않아요.
- 질문 문장에 넣으면 이슈 코드 뒤 조사(과/와)가 숫자 소리에 따라 바뀌어요(T2-첫줄 결정기록 3-7). 이름표는 조사가 필요 없어요.

### 5-3. 두 번째 화면도 전부 보여 줘요 (결정)

- 줄이는 안(제목 + "바로 앞과 같은 변경" + 이슈 줄)을 냈지만, 부건이 지금처럼 전부 보여 주기로 했어요.

### 5-4. 알았나는 "오늘 알림" 기준 (결정)

- 두 번째 이슈에서 "이미 알고 있었나요?"를 물으면 방금 첫 화면에서 봤기 때문에 "알았다"를 고르기 쉬워요. 그러면 핵심 지표인 "몰랐다" 수가 실제보다 적게 잡혀요.
- 첫 답을 옮겨 적고 다시 묻지 않는 방법도 있었지만, 착수 문서의 "이슈마다 따로 답한다"를 지키는 쪽을 골랐어요.
- 두 번째 이슈에서만 문구를 바꾸면 같은 질문이 두 가지 모양이 돼서, 모든 경우에 같은 문구를 써요 (Claude 제안).

### 5-5. 기록 줄에 내가 한 답 (결정)

- 착수 문서 5장은 T5에서 "내가 한 답"을 반드시 보여 주라고 해요. 앞 문서의 `✓ 기록했어요.`에는 없었어요.
- 문장(`SIL-34에 '관계있다 · 몰랐다'로 기록했어요.`)은 이유나 직접 쓴 글이 들어가면 길고 어색해져요. 이름표처럼 나열하면 어떤 답이든 같은 모양이고 조사 문제도 없어요.

### 5-6. 직접 쓴 글은 다시 묻고 메모로 (결정, 새 제안)

- 쓴 글을 그대로 답으로 기록하면 "몰랐다" 수를 셀 때 사람이 하나씩 읽고 나눠야 해요. 관계 질문에 글을 쓰면 다음 질문(알았나/이유)을 무엇으로 할지도 정할 수 없어요.
- 선택 화면이 "Type something."을 자동으로 붙이고 우리가 뺄 수 없어서(8장 15·16번), 쓴 글을 버리지 않고 메모로 남겨요.
- 시안용 MCP 서버도 보기 밖의 답을 거절해요. Claude가 규칙을 놓쳐도 기록이 섞이지 않아요 (Claude 제안).

### 5-7. 닫고 넘어가면 작업은 진행, 한 줄로 알림 (결정, 새 제안)

- 앞 시안은 답할 때까지 작업을 입력할 때마다 상세와 질문이 다시 떴어요. 급한 작업을 할 때 매번 막혀요.
- 그렇다고 아무것도 안 띄우면 답을 받지 못해요(앞 문서 8장 7번, 방식 3). 부건이 "작업은 진행하되 한 줄로 알리고, 거기서 확인하는 방법을 적어 두자"고 정했어요.
- hooks는 사용자가 선택 화면을 닫았다는 것을 직접 알 수 없어요. 그래서 "이번 세션에서 이미 물었는데 남아 있다"로 구분해요 (Claude 제안). Claude Code를 다시 켜면 세션이 바뀌어 처음처럼 물어요.

### 5-8. 다시 부르는 말은 "결정 사항 확인" (결정, 10/12 고침)

- 처음 낸 `변경 확인`은 부건이 문제를 짚었어요. 개발 중에 "코드 바뀐 것 보자"는 뜻으로 `변경 확인`만 입력할 수 있어서, 그때 알림 질문이 엉뚱하게 떠요. 0건이면 "모두 확인했어요"가 떠서 더 엉뚱해요.
- 처음에는 위키 용어를 넣어 `기준 변경 확인`으로 정했고, 10/12 용어를 "결정 사항"으로 바꾸면서 부건이 `결정 사항 확인`으로 줄였어요(5-11). 이 말도 개발 중에 우연히 그것만 칠 일이 거의 없어요. 입력 전체가 같을 때만 반응해서 문장 속에 들어간 경우도 걸리지 않아요.
- 답할 게 없을 때의 문구는 처음에 T2-첫줄 결정기록 5장의 후보 `✓ 나에게 온 변경을 모두 확인했어요.`를 썼고, 10/12 `✓ 확인할 변경이 없어요.`로 바꿨어요(5-11). 그 문서의 "직접 호출하는 명령"이 이 입력이에요.

### 5-9. 건수 숫자는 노란 굵은 글자 (결정)

- 부건이 숫자를 배경색 대신 글자색으로 바꿔 보자고 했고, 색은 뜻을 기준으로 골랐어요 (Claude 제안).
  - 빨강은 오류·삭제, 초록은 성공·완료(이 도구의 `✓`, `[완료]`)라서 맞지 않아요.
  - **노랑은 "주의해서 봐야 할 대기 중인 것"**이라 답을 기다리는 변경 수와 뜻이 맞아요. 상세 화면 형광펜(바뀐 부분)과 같은 계열이라 "노랑 = 봐야 할 것"이 이어져요.
  - 청록은 중립적인 안내, 파랑은 링크, 자주는 정해진 뜻이 거의 없어요.
- 숫자 한 글자만 색이 바뀌면 조용해서 굵게를 함께 써요.
- 노란 글자는 Tango Light 흰 배경에서 대비가 약 2.5:1로 낮아요(흐름 결정기록 5-8에서 "바뀐 부분" 글자를 노랗게 했다가 버린 이유). 이번에는 숫자 한 글자라 덜 치명적이에요. 미리보기를 보고 부건이 이대로 가기로 했어요(10/11). 나중에 흐리다는 의견이 나오면 다음 후보는 청록(약 3.5:1)이에요.

### 5-10. 기록 줄 둘째 줄은 "다음 작업부터 바뀐 결정 사항을 따라요." (결정)

- 착수 문서 T5 문구 "에이전트가 바뀐 결정 사항을 다시 읽었어요"를 부건이 빼 보자고 했어요.
- 이 문장의 역할은 "에이전트에게 따로 말하지 않아도 새 기준대로 일한다"고 안심시키는 거예요. 하지만 실제로 바로 다시 읽는지는 확실하지 않아요. 위키 `notify.answer.next-run-context`는 "다음 실행부터"예요.
- 그래서 빼지 않고, 위키에 맞게 문구를 바꿨어요. 실제 동작은 민수님 확인이 필요해요(민수-5).

### 5-11. 용어는 "결정 사항"과 "확인할 변경" (결정, 위키는 나중에)

- 위키 항목 하나를 위키는 "기준", 착수 문서와 SIL-69·71·73·74는 "결정 사항"으로 불렀고, 시안 상세 맨 위에는 어느 자료에도 없는 "규칙"까지 섞여 있었어요([SIL-68-맞춰야-할-용어.md](SIL-68-맞춰야-할-용어.md) 1번).
- 부건이 화면에서는 **결정 사항**으로 정했어요. 착수 문서와 SIL-71이 이미 그 말을 쓰고 있어요.
- 답해야 하는 항목도 네 가지로 불렀어요(확인할 규칙 변경 사항, 답하지 않은 기준 변경, 확인할 변경, 나에게 온 변경). 위키 용어대로 **확인할 변경** 하나로 맞췄어요(같은 문서 2번, Claude 제안).
- 위키 `copy.term.standard`("기준", 결정 사항은 쓰지 않음)와 달라져요. 이번에는 시안만 바꾸고, 위키는 신지님·호윤님과 확정한 뒤 SIL-64에서 "기준"이라는 말을 한 번에 바꿀 때 함께 고쳐요(부건 결정).
- 바뀐 곳: 켤 때 첫 줄, 상세 맨 위, 변경 줄(신규·폐기), 기록 줄 둘째 줄, 닫은 뒤 한 줄, 다시 부르는 말, 0건 문구, 이유 보기 설명.
