## 1. 먼저 지킬 규칙

1. **타입은 `packages/core/src/types/`에만 만들어요.** 다른 패키지에서 같은 모양을 다시 만들지 않아요. 한 파일 안에서만 쓰는 모양은 예외예요(9절).
2. **가져오는 곳은 세 군데예요.** 타입·에러·규칙 상수는 `@sil/core`에서 가져와요. DB를 부르는 함수는 Node(MCP 서버, 명령어)에서는 `@sil/core/node`, 웹 앱에서는 `@sil/core/data`에서 가져와요. 둘은 같은 함수예요 (D50). `@sil/core/node`는 Node 전용이라 웹 앱 화면에서는 가져오지 않아요 (린트가 막아요).

   ```ts
   import type { PendingCheck, StandardVersion } from '@sil/core';
   import { isSilError } from '@sil/core';
   // MCP 서버, 명령어(Node)
   import { listPendingChecks, saveStandard } from '@sil/core/node';
   // 웹 앱(브라우저)은 같은 함수를 '@sil/core/data'에서 가져와요
   ```

3. **이름 바꾸기는 core의 DB 함수(`@sil/core/data`)가 해요.** 코드는 camelCase(`alwaysOn`), DB 칸은 snake_case(`always_on`)예요. DB 행을 그대로 다른 패키지에 넘기지 않아요. 표를 직접 읽거나 쓰지도 않아요. 쓰기는 데이터베이스 함수(`save_standard` 등)로만 해요.
4. **비어 있을 수 있는 칸을 두 가지로 구분해요.**
   - `X | null`: 읽은 결과에서 값이 없을 수 있다는 뜻이에요. `undefined`로 돌려주지 않아요.
   - `x?:`: 입력에서 넣지 않아도 되는 칸에만 써요.
5. **시각은 `IsoDateTime`이에요.** ISO 문자열로 주고받아요. 예: `'2026-10-13T05:13:00.000Z'`. `Date` 객체를 넘기지 않아요.
6. **선택지 값은 영어 코드로 저장해요.** 예: `'in_progress'`, `'ai_chat'`. 화면에 쓰는 말은 `rules.ts`의 라벨 표에서 꺼내요(7절). 한국어 문장을 코드 값으로 쓰지 않아요.
7. **사람은 이름 문자열 하나로만 가리켜요** (`PersonRef`). 로그인 ID나 이메일을 넣지 않아요.
8. **답 타입의 이름은 `Answer`예요.** `Response`는 fetch의 `Response`와 이름이 겹쳐요. 가져오기를 빠뜨려도 오류가 나지 않아서 엉뚱한 타입이 조용히 쓰여요.

## 2. 같은 것을 부르는 이름

착수 안내, 화면, 코드, DB가 같은 것을 서로 다른 말로 불러요. 이 표가 연결표예요.

| 착수 안내 v2 (화면) | 최대 길이 | 코드 (타입.칸)                                                    | DB (표.칸)                                           |
| ------------------- | --------- | ----------------------------------------------------------------- | ---------------------------------------------------- |
| 결정 사항           |           | `Standard` (바뀌지 않는 부분) + `StandardVersion` (버전)          | `standards` + `standard_versions`                    |
| 결정 사항 ID        | 60자      | `Standard.id`, `StandardId`                                       | `standards.id`                                       |
| 제목                | 40자      | `StandardVersion.title` (버전마다)                                | `standard_versions.title`                            |
| 값 / 지금 값        | 120자     | `StandardVersion.value`                                           | `standard_versions.value`                            |
| 이전 값             | 120자     | 칸이 없어요. 바로 앞 버전의 `value`예요 (8절)                     | 없음                                                 |
| 이유                | 120자     | `StandardVersion.reason`                                          | `standard_versions.reason`                           |
| 버전                |           | `StandardVersion.version` (1부터)                                 | `standard_versions.version`                          |
| 누가 바꿨나         | 10자      | `StandardVersion.changedBy`                                       | `standard_versions.changed_by`                       |
| AI가 찾았나         |           | `StandardVersion.aiDetected`                                      | `standard_versions.ai_detected`                      |
| 출처 (AI 대화/코드) |           | `StandardVersion.source` (`'ai_chat'` / `'code'`)                 | `standard_versions.source`                           |
| 언제                |           | `StandardVersion.createdAt`                                       | `standard_versions.created_at`                       |
| 되돌림인가          |           | `StandardVersion.isRevert`                                        | `standard_versions.is_revert`                        |
| 항상 적용           |           | `StandardVersion.alwaysOn` (버전마다), `Standard.alwaysOn` (최신) | `standard_versions.always_on`, `standards.always_on` |
| 이슈 번호           | 8자       | `Issue.key`, `IssueKey`                                           | `issues.key`                                         |
| 이슈 제목           | 80자      | `Issue.title`                                                     | `issues.title`                                       |
| 담당자              | 10자      | `Issue.assignee`                                                  | `issues.assignee`                                    |
| 이슈 상태           |           | `Issue.status` (`'in_progress'` / `'done'`)                       | `issues.status`                                      |
| 연결된 결정 사항 ID |           | `Issue.standardIds`                                               | `issue_standards` 표 (이슈 하나에 여러 줄)           |
| 확인할 변경         |           | `PendingCheck`                                                    | `pending_checks`                                     |
| 확인할 변경 상태    |           | `PendingCheck.status` (`'pending'` 등, 5절)                       | `pending_checks.status`                              |
| 받는 사람           | 10자      | `PendingCheck.recipient`                                          | `pending_checks.recipient`                           |
| 마지막으로 본 버전  |           | `PendingCheck.lastSeenVersion`                                    | `pending_checks.last_seen_version`                   |
| 만든 시각           |           | `PendingCheck.createdAt`                                          | `pending_checks.created_at`                          |
| 답                  |           | `Answer`                                                          | `answers`                                            |
| 관계있다 / 관계없다 |           | `Answer.affected` (`true` / `false`)                              | `answers.affected`                                   |
| 알았다 / 몰랐다     |           | `Answer.known` (`true` / `false`)                                 | `answers.known`                                      |
| 관계없는 이유       | 100자     | `Answer.unaffectedReason`                                         | `answers.unaffected_reason`                          |
| 답한 곳             |           | `Answer.channel` (`'terminal'` / `'app'`)                         | `answers.channel`                                    |
| 답한 시각           |           | `Answer.answeredAt`                                               | `answers.answered_at`                                |

- **최대 길이는 화면 기준이에요** (착수 안내 5·7절). 저장할 때 막는 건 관계없는 이유 100자뿐이에요(DB). 제목이 40자를 넘으면 저장은 되고 경고만 와요(`checkStandardWording`). 나머지는 화면에서 넘침을 처리해요.
- 코드와 팀 위키 `용어.md`는 "결정 사항"을 **기준**(standard)이라고 불러요. 둘은 같은 거예요.
- "관계있다"를 `related`나 `relation`으로 쓰지 않아요. 코드 이름은 `affected`예요 (`용어.md`).

## 4. 기준 (`standard.ts`)

### `Standard` — 기준의 바뀌지 않는 부분

| 칸                 | 타입                 | 비어 있나 | DB 칸               | 뜻                                                                                                                                                             |
| ------------------ | -------------------- | --------- | ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`               | `StandardId`         | 아니요    | `id`                | 한 번 정하면 바뀌지 않아요                                                                                                                                     |
| `area`             | `string`             | 아니요    | `area`              | 영역. 비우고 저장하면 ID 앞부분(`app`)이 돼요                                                                                                                  |
| `title`            | `string`             | 아니요    | `title`             | **최신 버전**의 제목이에요. 버전마다의 제목은 `StandardVersion.title`                                                                                          |
| `alwaysOn`         | `boolean`            | 아니요    | `always_on`         | **최신 버전**의 항상 적용이에요. 폐기하면 `false`. 위키 전체에서 10개까지예요                                                                                  |
| `status`           | `StandardStatus`     | 아니요    | `status`            | 지우지 않고 폐기로 바꿔요                                                                                                                                      |
| `replacedBy`       | `StandardId \| null` | 예        | `replaced_by`       | 폐기됐다면 대신 쓰는 기준                                                                                                                                      |
| `deprecatedReason` | `string \| null`     | 예        | `deprecated_reason` | 폐기한 이유. 사용 중이면 `null`                                                                                                                                |
| `locked`           | `boolean`            | 아니요    | `locked`            | 잠금. 코드는 아직 잠긴 기준을 AI가 고치지 못하게 막아요(`STANDARD_LOCKED`). 위키 v2는 잠금 기준을 폐기했어요(wiki.lock.human-first). 막기를 뺄지는 따로 정해요 |

- DB에는 `deprecated_by`, `deprecated_at`, `created_at`, `updated_at`, `current_version`도 있어요. `current_version`은 `StandardHistory.currentVersion`으로 읽고, 나머지는 타입에 넣지 않았어요.
- `StandardStatus` = `'active' | 'deprecated'` (사용 / 폐기)

### `StandardVersion` — 기준 버전 (바뀔 때마다 한 줄)

| 칸                  | 타입                    | 비어 있나 | DB 칸                 | 뜻                                                                            |
| ------------------- | ----------------------- | --------- | --------------------- | ----------------------------------------------------------------------------- |
| `standardId`        | `StandardId`            | 아니요    | `standard_id`         |                                                                               |
| `version`           | `number`                | 아니요    | `version`             | 1부터 하나씩 올라가요                                                         |
| `title`             | `string`                | 아니요    | `title`               | 버전마다 남겨요 (SIL-57). 40자를 넘으면 경고만 해요 (2절)                     |
| `value`             | `string`                | 아니요    | `value`               | 기준 내용 한 문장 (화면 기준 120자, 2절)                                      |
| `reason`            | `string`                | 아니요    | `reason`              | 없으면 저장을 거절해요                                                        |
| `alwaysOn`          | `boolean`               | 아니요    | `always_on`           | **그 버전의** 항상 적용. 되돌리면 그 버전의 값으로 돌아가요 (2026-10-10 추가) |
| `evidence`          | `string \| null`        | 예        | `evidence`            | 근거. 예전 위키 값을 저장만 해요                                              |
| `scope`             | `StandardScope \| null` | 예        | `scope`               | 적용 범위. 저장만 해요                                                        |
| `changedBy`         | `PersonRef \| null`     | 예        | `changed_by`          | 누가 바꿨나. MCP로 저장하면 그 세션의 사용자 이름이 들어가요                  |
| `changedByActor`    | `Actor`                 | 아니요    | `changed_by_actor`    | AI가 저장했으면 `'ai'`                                                        |
| `aiDetected`        | `boolean`               | 아니요    | `ai_detected`         | AI가 PR을 읽고 찾아낸 변경이면 `true` (화면의 "PR에서 찾음")                  |
| `isRevert`          | `boolean`               | 아니요    | `is_revert`           | 앞선 버전 값과 같아졌으면 `true`                                              |
| `revertedToVersion` | `number \| null`        | 예        | `reverted_to_version` | 되돌림이면 어느 버전으로 돌아갔는지                                           |
| `source`            | `StandardSource`        | 아니요    | `source`              | 출처                                                                          |
| `createdAt`         | `IsoDateTime`           | 아니요    | `created_at`          | 저장한 시각                                                                   |

- `StandardScope` = `{ code: string[]; api: string[]; screen: string[]; doc: string[] }`. 칸이 빠진 채로 저장하면 빈 목록으로 채워요.
- `StandardSource` = `'code' | 'ai_chat' | 'figma' | 'meeting' | 'slack' | 'wiki'`
  - 화면에는 "AI 대화"(`ai_chat`)와 "코드"(`code`) 두 가지만 나와요.
  - `wiki`는 `sil import`로 예전 위키에서 옮겨 온 버전이에요. MCP의 `save_standard`는 `wiki`를 받지 않아요.

### 쓰기 입력과 결과

`SaveStandardInput` — 새 기준 또는 새 버전 저장 (`saveStandard()`, DB 함수 `save_standard`)

| 칸               | 타입                             | 필수   | 뜻                                                                         |
| ---------------- | -------------------------------- | ------ | -------------------------------------------------------------------------- |
| `id`             | `StandardId`                     | **예** |                                                                            |
| `title`          | `string`                         | **예** |                                                                            |
| `value`          | `string`                         | **예** |                                                                            |
| `reason`         | `string`                         | **예** |                                                                            |
| `alwaysOn`       | `boolean`                        | **예** | 고칠 때도 지금 값을 그대로 넣어요. 이 값이 새 버전 줄에 남아요             |
| `baseVersion`    | `number`                         | **예** | 내가 보고 고친 버전. 새 기준이면 `0`. 그사이 바뀌었으면 `VERSION_CONFLICT` |
| `evidence`       | `string \| null`                 | 아니요 | `aiDetected`가 `true`면 꼭 넣어요                                          |
| `scope`          | `Partial<StandardScope> \| null` | 아니요 |                                                                            |
| `area`           | `string`                         | 아니요 | 비우면 새 기준은 ID 앞부분, 고칠 때는 그대로                               |
| `source`         | `StandardSource`                 | 아니요 | 기본 `'ai_chat'`                                                           |
| `changedByActor` | `Actor`                          | 아니요 | 기본 `'ai'`                                                                |
| `changedBy`      | `PersonRef \| null`              | 아니요 |                                                                            |
| `aiDetected`     | `boolean`                        | 아니요 | 기본 `false`. 바뀐 기준 찾기(경하)가 PR에서 찾았을 때 `true`               |
| `locked`         | `boolean`                        | 아니요 | 사람만 넣을 수 있어요. AI가 넣으면 거절돼요                                |

- 필수 칸은 ID, 제목, 값, 이유, 항상 적용 5개예요 (SIL-65). `baseVersion`은 칸이 아니라 동시 수정을 막는 번호라서 따로 받아요.
- `SaveStandardResult` = `{ standardId; version; isRevert; revertedToVersion: number | null; previousValue: string | null; savedAt: IsoDateTime; changelogLine: string }`
  - `previousValue`: 바로 앞 버전의 값이에요. 새 기준이면 `null`이에요.
  - `changelogLine`: `team-wiki/CHANGELOG.md`에 붙일 한 줄이에요.
- `RevertStandardInput` = `{ id; toVersion; reason; baseVersion; evidence?; source?; changedByActor?; changedBy? }`
  - 되돌림도 새 버전으로 쌓여요. 제목·값·적용 범위·항상 적용을 `toVersion`의 것으로 돌려요.
  - 결과 모양은 `SaveStandardResult`와 같아요.
- `DeprecateStandardInput` = `{ id; reason; baseVersion; replacedBy?; changedByActor?; changedBy? }`
- `DeprecateStandardResult` = `{ standardId; status: 'deprecated'; replacedBy: StandardId | null }`

### 충돌 보류

`Conflict` — 같은 버전을 보고 늦게 저장해서 저장되지 못한 변경이에요. 버리지 않고 보류로 남겨요 (detect.conflict.hold).

| 칸                                       | 타입                          | 뜻                                     |
| ---------------------------------------- | ----------------------------- | -------------------------------------- |
| `id`                                     | `string` (uuid)               |                                        |
| `standardId`                             | `StandardId`                  |                                        |
| `baseVersion` / `currentVersion`         | `number`                      | 보고 고친 버전 / 그때 이미 저장된 버전 |
| `title`, `value`                         | `string`                      | 저장하려던 내용                        |
| `reason`, `evidence`                     | `string \| null`              |                                        |
| `proposedBy` / `proposedByActor`         | `PersonRef \| null` / `Actor` |                                        |
| `source` / `aiDetected`                  | `StandardSource` / `boolean`  |                                        |
| `status`                                 | `'held' \| 'resolved'`        | 보류 / 정리됨                          |
| `resolution`, `resolvedBy`, `resolvedAt` | `string \| null` …            | 사람이 어떻게 정했는지                 |
| `createdAt`                              | `IsoDateTime`                 |                                        |

- `HoldConflictResult` = `{ held: boolean; conflictId: string | null; currentVersion: number }`. 지금 버전과 내용이 같으면 충돌이 아니라서 `held: false`예요.
- DB `conflicts` 표에는 `scope`도 있지만 타입에서는 읽지 않아요.

## 5. 이슈·확인할 변경·답 (`notify.ts`)

> **"v2 밖" 표시**가 붙은 값은 예전 팀 위키를 따라 만들어 둔 거예요. 착수 안내 v2의 "하지 않는 것"과 상태 4가지에 없고, 팀 위키 v2(10/11, SIL-64)도 관련 기준을 폐기했어요: 답 취소(notify.answer.cancel), 완료된 이슈 다시 열기(notify.answer.reopen-done), 담당자가 바뀔 때 옮기기(notify.pending.owner-change), Slack(notify.channel.three). 새 기능은 이 값에 기대지 않아요. 타입과 DB에서 빼는 일은 따로 해요.

### `Issue`

| 칸            | 타입             | 비어 있나 | DB                   | 뜻                                 |
| ------------- | ---------------- | --------- | -------------------- | ---------------------------------- |
| `key`         | `IssueKey`       | 아니요    | `issues.key`         | 예: `'#5'` (화면 기준 8자, 2절)    |
| `title`       | `string`         | 아니요    | `issues.title`       | 화면 기준 80자 (2절)               |
| `assignee`    | `string \| null` | 예        | `issues.assignee`    | 없으면 확인할 변경을 만들지 않아요 |
| `status`      | `IssueStatus`    | 아니요    | `issues.status`      |                                    |
| `standardIds` | `StandardId[]`   | 아니요    | `issue_standards` 표 | 1개 이상                           |

- `IssueStatus` = `'in_progress' | 'done'` (진행 중 / 완료). 완료된 이슈에도 알림은 가요.
- `SaveIssueInput` = `Issue`와 같아요.
- `SaveIssueResult` = `{ issueKey; created: boolean; standardIds; movedChecks: number }`. `movedChecks`는 담당자가 바뀌어서 새 담당자에게 옮긴 확인할 변경 수예요 (**v2 밖**).

### `PendingCheck` — 확인할 변경 (기준 버전 1개 × 이슈 1개마다 한 줄)

| 칸                | 타입                  | 비어 있나 | DB 칸               | 뜻                                                                                                                   |
| ----------------- | --------------------- | --------- | ------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `id`              | `string` (uuid)       | 아니요    | `id`                |                                                                                                                      |
| `standardId`      | `StandardId`          | 아니요    | `standard_id`       |                                                                                                                      |
| `version`         | `number`              | 아니요    | `version`           | 확인할 기준 버전                                                                                                     |
| `issueKey`        | `IssueKey`            | 아니요    | `issue_key`         | 이슈 제목·상태는 `Issue`에서 읽어요                                                                                  |
| `recipient`       | `string \| null`      | 예        | `recipient`         | 받는 사람. `null`이면 담당자 없음. 위키 v2는 담당자 없는 이슈에 확인할 변경을 만들지 않아요(notify.pending.no-owner) |
| `status`          | `PendingCheckStatus`  | 아니요    | `status`            |                                                                                                                      |
| `lastSeenVersion` | `number \| null`      | 예        | `last_seen_version` | 받는 사람이 마지막으로 확인한 버전                                                                                   |

`PendingCheckStatus`

| 값                   | 화면 말 (`PENDING_CHECK_STATUS_LABELS`) | 착수 안내 v2 | 메모                             |
| -------------------- | --------------------------------------- | ------------ | -------------------------------- |
| `'pending'`          | 대기                                    | 있음         | 답을 기다려요                    |
| `'answered'`         | 답함                                    | 있음         |                                  |
| `'superseded'`       | 새 버전으로 대체됨                      | 있음         | 답하기 전에 또 바뀌어서 닫혔어요 |
| `'auto_closed'`      | 자동 닫힘                               | 있음         | 화면에 나오지 않아요             |
| `'answer_cancelled'` | 답 취소                                 | **v2 밖**    | 다시 답을 기다리는 상태로 쳐요   |

- 아직 답을 기다리는 상태인지는 `isOpenPendingCheck(status)`로 판단해요. 상태 값을 직접 비교하지 않아요.

### `Answer` — 답

| 칸                                           | 타입              | 비어 있나                     | DB 칸                          | 뜻                                              |
| -------------------------------------------- | ----------------- | ----------------------------- | ------------------------------ | ----------------------------------------------- |
| `id`                                         | `string` (uuid)   | 아니요                        | `id`                           |                                                 |
| `pendingCheckId`                             | `string`          | 아니요                        | `pending_check_id`             | 어느 확인할 변경에 대한 답인지                  |
| `affected`                                   | `boolean`         | 아니요                        | `affected`                     | 관계있다 `true` / 관계없다 `false`              |
| `known`                                      | `boolean \| null` | `affected`가 `false`면 `null` | `known`                        | 알았다 `true` / 몰랐다 `false`                  |
| `unaffectedReason`                           | `string \| null`  | `affected`가 `true`면 `null`  | `unaffected_reason`            | 관계없는 이유. 100자 이하, 관계없다면 꼭 있어요 |
| `reworkNote`                                 | `string \| null`  | 예                            | `rework_note`                  | 몰랐다일 때만. 모르고 계속했다면 다시 할 일     |
| `channel`                                    | `AnswerChannel`   | 아니요                        | `channel`                      | 답한 곳                                         |
| `elapsedSeconds`                             | `number \| null`  | 예                            | `elapsed_seconds`              | 알림을 연 순간부터 답할 때까지 걸린 초          |
| `answeredBy`                                 | `string \| null`  | 예                            | `answered_by`                  | 답한 사람 이름                                  |
| `answeredAt`                                 | `IsoDateTime`     | 아니요                        | `answered_at`                  |                                                 |
| `cancelledAt`, `cancelledBy`, `cancelReason` | `… \| null`       | 예                            | `cancelled_*`, `cancel_reason` | 답 취소 (**v2 밖**)                             |

- `AnswerChannel` = `'terminal' | 'app' | 'slack'`. `'slack'`은 **v2 밖**이에요 (착수 안내 2: Slack 알림과 답하기를 하지 않아요).
- 핵심 지표 "몰랐다"는 `affected && known === false && cancelledAt === null`인 답의 수예요.
- DB가 칸 조합을 막아요. 관계있다면 `known`이 꼭 있고 `unaffectedReason`이 없어요. 관계없다면 그 반대예요.

### 답 쓰기와 읽기

- `SaveAnswerInput` = `{ pendingCheckId; answeredBy; affected; known?; unaffectedReason?; reworkNote?; channel; elapsedSeconds?; reopenIssue? }`
  - 받은 사람만 답할 수 있어요. 다른 사람이면 `FORBIDDEN`, 이미 닫혔으면 `PENDING_CLOSED`예요.
  - `reopenIssue`는 **v2 밖**이에요 (착수 안내 2: 완료된 이슈를 다시 열지 않아요. 위키 v2에서 notify.answer.reopen-done 폐기).
- `SaveAnswerResult` = `{ answerId; pendingCheckId; issueKey; issueStatus: IssueStatus; issueReopened: boolean }`. `issueReopened`는 **v2 밖**이에요.
- `CancelAnswerInput` = `{ answerId; cancelledBy; reason }`, `CancelAnswerResult` = `{ answerId; pendingCheckId; reopened: boolean }`. 둘 다 **v2 밖**이에요 (위키 v2에서 notify.answer.cancel 폐기).
- `AnswerRecord`: 응답 기록 한 줄의 재료예요 (DB 뷰 `answer_records`). `sil export`가 14칸 표로 바꿔요.
  - 칸: `answerId`, `answeredAt`, `standardId`, `version`, `previousValue`, `value`, `changedBy`, `changedByActor`, `aiDetected`, `evidence`, `issueKey`, `answeredBy`, `affected`, `known`, `elapsedSeconds`, `unaffectedReason`, `reworkNote`, `channel`, `cancelledAt`
  - `previousValue`는 받는 사람이 마지막으로 본 값이에요. 없으면 바로 앞 버전의 값이에요.
- `AffectedCheck`: "관계있다"고 답한 확인할 변경이에요 (DB 뷰 `affected_checks`). 다음 세션부터 작업 맥락에 넣어요.
  - 칸: `answeredBy`, `standardId`, `version`, `issueKey`, `issueStatus`, `answeredAt`

## 7. 에러 (`errors.ts`)와 규칙 상수 (`rules.ts`)

### 에러

모든 실패는 `SilError`로 던져요. 분기는 `message`가 아니라 `code`로 해요. 문구는 바뀔 수 있어요.

```ts
try {
  await saveStandard(input);
} catch (error) {
  if (isSilError(error) && error.code === 'VERSION_CONFLICT') {
    // 최신 버전을 다시 읽고 사람에게 물어요
  }
  throw error;
}
```

| `SilErrorCode`      | 언제                                                                        | 받은 쪽이 할 일                                        |
| ------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------ |
| `DB_NOT_CONFIGURED` | `.env`에 Supabase 주소·키가 없어요 (`DbNotConfiguredError`)                 | 서버 설정을 채워요                                     |
| `NOT_IMPLEMENTED`   | 자리만 만든 기능을 불렀어요 (`NotImplementedError`)                         | 문구에 적힌 담당 이슈를 봐요                           |
| `INVALID_ENV`       | 환경 변수 모양이 틀렸어요                                                   | 문구에 적힌 변수를 고쳐요                              |
| `VALIDATION_FAILED` | 필수 칸이 비었거나 모양이 틀렸어요. 바뀐 내용이 없는 저장도 이 코드예요     | 빠진 칸을 사람에게 묻고 다시 저장해요. 지어내지 않아요 |
| `NOT_FOUND`         | 없는 기준·이슈·확인할 변경                                                  | ID를 다시 찾아요                                       |
| `STANDARD_LOCKED`   | 잠긴 기준을 AI가 고치려 했어요                                              | 사람에게 알려요                                        |
| `VERSION_CONFLICT`  | 그사이 다른 사람이 고쳤어요 (변경은 충돌로 보류돼요)                        | `get_standard`로 최신을 보고 사람에게 확인해요         |
| `ALWAYS_ON_LIMIT`   | 항상 적용이 10개를 넘어요 (되돌리기 포함)                                   | 하나를 빼거나 항상 적용이 아닌 기준으로 저장해요       |
| `FORBIDDEN`         | 받은 사람이 아닌데 답했어요                                                 | 답하지 않아요                                          |
| `PENDING_CLOSED`    | 이미 답했거나 닫힌 확인할 변경에 또 답했어요                                | 화면에서 그 알림만 조용히 닫아요                       |
| `CHANGE_LIMIT`      | 최근 24시간 안에 이미 두 번 바뀐 기준을 PR에서 찾은 변경이 또 바꾸려 했어요 | 저장하지 않고 사람에게 물어요                          |
| `DB_ERROR`          | 그 밖의 DB 문제 (연결, 권한, 모양이 코드와 다름)                            | 문구대로 확인해요                                      |

- 도우미: `isSilError(e)`, `isSilErrorCode(value)`, `SIL_ERROR_CODES`(전체 목록)

## 8. 자주 헷갈리는 것

- **"이전 값"은 어디에 있나요?** 따로 저장하지 않아요. 읽는 곳에 따라 다음 중 하나를 써요.
  - 버전 기록: 바로 앞 버전의 `value`
  - 저장 결과: `SaveStandardResult.previousValue`
  - 응답 기록: `AnswerRecord.previousValue` (받는 사람이 마지막으로 본 값이 먼저예요)
  - 값이 없으면 "새 결정 사항"으로 보여 줘요.
- **항상 적용은 어느 쪽을 읽나요?** 지금 값은 `Standard.alwaysOn`을 읽어요.
  - 사용 중인 기준에서는 최신 버전의 `StandardVersion.alwaysOn`과 늘 같아요.
  - 폐기하면 `Standard.alwaysOn`만 `false`가 돼요. 폐기는 새 버전을 만들지 않아요.
  - 과거 버전의 값은 `StandardVersion.alwaysOn`에 있어요. 2026-10-10 전에 쌓인 버전은 그때 기준의 값으로 채워 두었어요.
- **제목은 어느 쪽을 읽나요?** 화면에서 "지금 제목"은 `Standard.title`(최신)이에요. 바뀐 내용을 보여 줄 때는 버전마다의 `StandardVersion.title`이에요.
- **버전 번호:** 1부터 시작해요. `baseVersion: 0`은 "새 기준"이라는 뜻이에요.
- **`known`이 `null`인 답:** 관계없다고 답한 거예요. "몰랐다"로 세지 않아요.
- **완료된 이슈:** 알림은 가지만 다시 열지는 않아요 (v2). `reopenIssue`를 쓰지 않아요.
- **`auto_closed`:** 화면에 보여 주지 않아요. 목록에서 걸러요.
- **MCP 도구 입력은 왜 zod인가요:** MCP SDK가 zod 스키마로 입력을 받아요. 그래서 입력 모양은 `apps/mcp-server/src/tools/`에 zod로 두고, 결과는 이 글의 타입을 그대로 써요. 입력 칸 이름은 `SaveStandardInput`과 같게 맞춰요.
  - 입력 모양 검사에 걸리면 `SilError`가 아니라 MCP SDK 오류("Input validation error: …")로 와요. 칸 이름과 한국어 문구(예: "제목(title)이(가) 비어 있어요")가 들어 있어요. 칸을 아예 빼도 같은 문구예요.
  - 모양 검사를 지난 뒤 DB 함수가 거절하면 `[VALIDATION_FAILED] …`처럼 에러 코드가 앞에 붙어 와요.

### 11-1. 화면이 데이터를 받는 길

```
화면(screens/) → api (SilApi) ─┬─ database.ts → @sil/core/data → Supabase (공용 키)
                               └─ mock.ts     → @sil/core 예시 데이터
```

- 화면은 데이터를 `apps/web/src/api`의 `api`로만 받아요. 화면에서 DB 함수를 바로 부르지 않아요.
- `api`는 Supabase 주소·키가 있으면 `database.ts`, 없으면 `mock.ts`예요. 어느 쪽인지는 `isMock`으로 알아요.
- 화면 코드가 가져오는 곳은 `@sil/core`(타입·라벨·예시 데이터)와 `./api`예요. `@sil/core/node`는 린트가 막아요.
- 함수를 더하는 순서: `SilApi`에 타입 → `database.ts`에 실제 동작(`@sil/core/data` 함수로) → `mock.ts`에 예시 버전. 하나라도 빠지면 타입 검사가 알려 줘요.

### 11-2. 지금 있는 약속

`AppInfo` — 메뉴 아래 상태 줄에 쓰는 앱 정보예요 (`api.getAppInfo()`).

| 칸         | 타입                                                                            | 뜻                                                                                                                                                 |
| ---------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `version`  | `string`                                                                        | `apps/web/package.json`의 버전 (`__APP_VERSION__`)                                                                                                 |
| `platform` | `'browser' \| 'installed'`                                                      | 브라우저 탭 / PWA로 설치한 앱 창. `currentPlatform()`이 정해요                                                                                     |
| `dataMode` | `DataMode \| 'mock'`                                                            | `'database'`(진짜 데이터) / `'mock'`(예시 데이터). `'none'`은 화면에서 쓰지 않아요                                                                 |
| `db`       | `{ ok: true; standardCount: number } \| { ok: false; message: string } \| null` | DB에 붙었는지. 예시 데이터면 `null`이에요. 못 붙었으면 `message`를 그대로 보여 줘요. 실패를 "변경 없음"으로 숨기지 않아요 (notify.error.not-empty) |

- `SilApi` = `{ getAppInfo(): Promise<AppInfo> }`. 지금은 이 함수 하나예요. 화면에 필요한 함수는 11-5에서 정해요.

**빌드할 때 들어가는 값** (`vite-env.d.ts`의 `ImportMetaEnv`)

| 이름                                           | 타입     | 뜻                                                                      |
| ---------------------------------------------- | -------- | ----------------------------------------------------------------------- |
| `import.meta.env.SIL_SUPABASE_URL`             | `string` | 루트 `.env`의 `SUPABASE_URL`. 없으면 빈 문자열이고 예시 데이터로 열려요 |
| `import.meta.env.SIL_SUPABASE_PUBLISHABLE_KEY` | `string` | 루트 `.env`의 `SUPABASE_PUBLISHABLE_KEY`(공용 키). 없으면 빈 문자열     |
| `__APP_VERSION__`                              | `string` | `apps/web/package.json`의 `version`                                     |

- 화면에 들어가는 환경 변수는 이 둘뿐이에요(`vite.config.ts`가 넣어요). 비밀 키나 MCP 토큰은 화면에 넣지 않아요.

**PWA** (`pwa.ts`)

| 이름                       | 모양                                  | 뜻                                                                                                |
| -------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `registerServiceWorker()`  | `() => void`                          | 배포본에서만 `sw.js`를 등록해요. 개발 중(`pnpm app:web`)에는 등록하지 않아요                      |
| `currentPlatform()`        | `() => 'browser' \| 'installed'`      | 설치한 앱 창으로 열었는지                                                                         |
| `useInstallPrompt()`       | `() => (() => Promise<void>) \| null` | 설치할 수 있으면 설치 창을 여는 함수, 아니면 `null`. "앱으로 설치" 버튼을 보일지 이 값으로 정해요 |
| `BeforeInstallPromptEvent` | `Event` + `prompt()`, `userChoice`    | 표준 DOM 타입에 아직 없는 설치 안내 이벤트(Chrome·Edge). `pwa.ts` 안에서만 써요                   |

- 서비스 워커(`public/sw.js`)는 앱 껍데기(HTML·JS·CSS·아이콘)만 저장해요. DB 응답은 저장하지 않아요. 고치면 `CACHE` 이름의 숫자를 올려요.

### 11-4. 화면에 보여 주는 규칙 (착수 안내 5절 → 타입 값)

| 화면 항목         | 읽는 값                                     | 보여 주는 방법                                                                                                              |
| ----------------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 결정 사항 제목    | `StandardVersion.title` (확인할 그 버전)    | 그대로                                                                                                                      |
| 이전 값 → 지금 값 | 이전 값(아래 규칙), `StandardVersion.value` | 이전 값이 `null`이면 "새 결정 사항"                                                                                         |
| 이유              | `StandardVersion.reason`                    | 그대로                                                                                                                      |
| 누가 바꿨나       | `StandardVersion.changedBy`                 | 이름만                                                                                                                      |
| AI가 찾았나       | `StandardVersion.aiDetected`                | `true`일 때만 "PR에서 찾음"                                                                                                 |
| 출처              | `StandardVersion.source`                    | `SOURCE_LABELS`로 "AI 대화에서 바꿈" / "코드에서 바꿈"                                                                      |
| 언제              | `StandardVersion.createdAt`                 | 오늘이면 "오후 2:13", 아니면 "10월 13일 오후 2:13" (보는 사람의 시간대)                                                     |
| 내 이슈           | `Issue.key`, `Issue.title`                  | 제목이 길면 끝을 줄여요(…)                                                                                                  |
| 이슈 상태         | `Issue.status`                              | `'done'`일 때만 "완료"                                                                                                      |
| 확인할 변경 상태  | `PendingCheck.status`                       | `PENDING_CHECK_STATUS_LABELS`. `auto_closed`는 목록에서 빼요. `answer_cancelled`는 대기와 같이 다뤄요(`isOpenPendingCheck`) |
| 답할 변경 개수    | `isOpenPendingCheck(status)`인 것의 수      | 0이면 빈 화면                                                                                                               |
| 관계 / 알았나     | `SaveAnswerInput.affected`, `known`         | 버튼 2개씩. 관계없다면 `known`을 보내지 않아요                                                                              |
| 관계없는 이유     | `SaveAnswerInput.unaffectedReason`          | 입력란 1개, 100자 (DB가 막아요)                                                                                             |
| 답한 곳           | `SaveAnswerInput.channel`                   | 웹 앱은 늘 `'app'`                                                                                                          |
| 확인에 쓴 시간    | `SaveAnswerInput.elapsedSeconds`            | 상세(A3)를 연 순간부터 답할 때까지의 초를 화면이 재요                                                                       |

**이전 값 고르기** (8절과 같은 규칙)

1. `PendingCheck.lastSeenVersion`이 있으면 그 버전의 `value`예요 (받는 사람이 마지막으로 본 값).
2. 없으면 바로 앞 버전(`version - 1`)의 `value`예요.
3. 둘 다 없으면(버전 1) `null`이에요 → "새 결정 사항".

버전 기록은 `getStandardHistory(standardId)`로 읽어요.

**답할 때 생기는 에러**

| 코드                | 언제                                           | 화면이 할 일                                                         |
| ------------------- | ---------------------------------------------- | -------------------------------------------------------------------- |
| `PENDING_CLOSED`    | 터미널에서 이미 답했거나, 또 바뀌어서 닫혔어요 | 에러를 띄우지 않고 그 항목만 조용히 닫아요 (notify.answer.one-place) |
| `FORBIDDEN`         | 받은 사람이 아니에요                           | 답하기 버튼을 보이지 않아요                                          |
| `VALIDATION_FAILED` | 관계없는 이유가 비었거나 100자를 넘어요        | 입력란 옆에 문구를 보여 줘요                                         |
| `DB_ERROR`          | 연결·권한 문제                                 | 메뉴 아래처럼 무엇을 확인할지 빨간 글씨로 보여 줘요                  |

### 11-5. 제안: 나에게 온 변경 약속 (아직 코드에 없어요)

> 민수님(구현)·신지님(화면)과 정한 뒤 `types.ts`에 넣고, 이 절을 11-2로 옮겨요. core에 이미 있는 함수(`listPendingChecks`, `getStandardHistory`, `listIssues`, `saveAnswer`)로 만들 수 있는 모양이에요.

```ts
import type {
  Issue,
  PendingCheck,
  SaveAnswerInput,
  SaveAnswerResult,
  StandardVersion,
} from '@sil/core';

/** 나에게 온 변경 한 건. A1(알림)·A2(목록)·A3(상세)이 같은 모양을 써요 */
export interface MyChange {
  /** 확인할 변경 (상태, 마지막으로 본 버전) */
  check: PendingCheck;
  /** 확인할 그 버전 (제목, 지금 값, 이유, 누가, 언제, 출처, AI가 찾았나) */
  version: StandardVersion;
  /** 11-4 "이전 값 고르기". null이면 "새 결정 사항" */
  previousValue: string | null;
  /** 내 이슈 (번호, 제목, 상태) */
  issue: Issue;
}

/** 나에게 온 변경에 답하기. 답한 사람과 답한 곳('app')은 api가 채워요 */
export type MyAnswerInput = Omit<
  SaveAnswerInput,
  'answeredBy' | 'channel' | 'reopenIssue'
>;

export interface SilApi {
  getAppInfo(): Promise<AppInfo>;
  /** 내 확인할 변경. 기본은 답할 것만(대기·답 취소), 오래된 것부터 */
  listMyChanges(me: string, status?: 'open' | 'all'): Promise<MyChange[]>;
  /** 답하기. 이미 닫혔으면 PENDING_CLOSED */
  answer(me: string, input: MyAnswerInput): Promise<SaveAnswerResult>;
  /** 내 확인할 변경이 생기거나 닫히면 부르는 구독. 돌려준 함수로 끊어요 (app.notify.realtime) */
  watchMyChanges(me: string, onChange: () => void): () => void;
}
```

**정할 것**

| 항목                          | 메모                                                                                                                                      |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 내 이름(`me`)을 어디서 받나요 | 로그인이 없어요(착수 안내 2절). 처음 열 때 이름을 고르고 브라우저에 저장하는 방법이 있어요                                                |
| 구독(`watchMyChanges`)        | DB는 `pending_checks`가 바뀌면 바로 알려 줘요(Realtime). 화면이 DB를 직접 부르지 않도록, 구독 함수를 `@sil/core/data`에 먼저 더해요       |
| OS 알림(A1)                   | 1단계는 창이 열려 있을 때만 와요(구독 + 브라우저 `Notification`). 창을 닫아도 오는 웹 푸시는 10/13 이후예요                               |
| 알림 꺼짐 상태(A2)            | 브라우저의 `Notification.permission`(`'default' \| 'denied' \| 'granted'`)을 그대로 써요. 권한은 사람이 버튼을 누른 뒤에만 물을 수 있어요 |
| 답한 시각(A4)                 | `SaveAnswerResult`에는 시각이 없어요. 답한 직후의 시각을 쓰거나 다시 읽어요                                                               |
| 목록 순서                     | `listPendingChecks`는 오래된 것부터예요. 화면 순서(안 본 것 먼저 / 최신순)는 SIL-42에서 정해요                                            |

### 11-6. 지금 화면 뼈대와 착수 안내 v2의 차이
