# 실행 방법

이 저장소는 세 가지로 실행해요.

| 어떻게                                | 무엇을 하나요                                                          | 바로 가기                        |
| ------------------------------------- | ---------------------------------------------------------------------- | -------------------------------- |
| [일반 실행](#1-일반-실행)             | 설치, MCP 서버 켜기, 웹 앱 화면 열기, 검사                             | `pnpm mcp:serve`, `pnpm app:web` |
| [Claude Code에서](#2-claude-code에서) | Claude Code에 MCP 서버 `haribo`를 등록하고, 대화 중에 위키 도구를 써요 | `pnpm mcp:register`              |
| [CLI에서](#3-cli에서-sil-명령어)      | `sil` 명령어로 위키 불러오기, 폐기, 내보내기, 백업을 해요              | `pnpm sil <명령>`                |

모든 명령은 저장소 맨 위 폴더(`haribo/`)에서 실행해요.

## 준비물

- **Node 24.18** (`.nvmrc`). nvm을 쓰면 `nvm install` 다음 `nvm use`. 빌드 없이 Node가 TypeScript를 바로 실행해서, 다른 버전이면 켜지지 않아요 (D48).
- **pnpm**. 없으면 `npm install -g pnpm`. 버전은 `package.json`에 적힌 11.25.0으로 자동으로 맞춰져요.
- **Git**
- **Claude Code**: 2번(Claude Code에서)에만 필요해요.
- Docker는 필요 없어요.

## 1. 일반 실행

### 처음 한 번

```bash
pnpm install
```

```bash
pnpm onboard
```

```bash
pnpm mcp:check
```

- `pnpm onboard`는 Node 버전, `.env`, DB, Claude Code 등록을 확인해요. `.env`가 없으면 `.env.example`을 복사해 만들어 줘요.
- `pnpm mcp:check`에서 "✔ MCP 서버가 HTTP로 답해요"가 나오면 성공이에요. `.env`에 Supabase 주소와 공용 키가 있으면 "✔ 데이터베이스 연결됨: 기준 N개"까지 나와요.
- `pnpm doctor`가 아니라 `pnpm onboard`예요. `pnpm doctor`는 pnpm 자체 검사예요.

### 켜기

| 하고 싶은 일             | 명령                                     | 주소                                                        |
| ------------------------ | ---------------------------------------- | ----------------------------------------------------------- |
| MCP 서버 켜기            | `pnpm mcp:serve`                         | http://127.0.0.1:3333/mcp                                   |
| 고치면서 MCP 서버 쓰기   | `pnpm mcp:dev`                           | 같은 주소. 파일을 저장하면 서버가 다시 켜져요               |
| 웹 앱 화면               | `pnpm app:web`                           | http://localhost:5173                                       |
| PWA(설치·오프라인) 확인  | `pnpm app:build` 다음 `pnpm app:preview` | http://localhost:4173                                       |
| 전체 검사 (PR 올리기 전) | `pnpm check`                             | 타입, 린트, 포맷, 테스트                                    |
| DB 규칙 검사             | `supabase/tests/*.sql`을 psql로 실행     | [README "데이터베이스"](../README.md#데이터베이스-supabase) |

- MCP 서버는 HTTP만 열어요. 토큰(`SIL_MCP_TOKENS`)이 비어 있으면 내 컴퓨터(localhost)에서 온 요청만 받아요.
- 웹 앱은 `.env`에 `SUPABASE_URL`과 `SUPABASE_PUBLISHABLE_KEY`가 있으면 진짜 DB에, 없으면 예시 데이터에 붙어요. 왼쪽 메뉴 아래에 어느 쪽인지 나와요.
- 끄려면 켠 터미널에서 `Ctrl+C`를 눌러요.

## 2. Claude Code에서

Claude Code에 MCP 서버 `haribo`를 등록하면, 어느 저장소에서 일하든 대화 중에 팀 기준을 찾고 고칠 수 있어요.

| 도구               | 하는 일                                   | 읽기만 |
| ------------------ | ----------------------------------------- | ------ |
| `ping`             | 서버·DB 연결, 누구로 들어왔는지 확인      | ✔      |
| `get_index`        | 목차: 항상 적용 기준, 기준 전체 목록      | ✔      |
| `search_standards` | 키워드, 영역, 코드 경로로 기준 찾기       | ✔      |
| `get_standard`     | 기준 하나의 최신 내용과 버전 기록         | ✔      |
| `save_standard`    | 새 기준·새 버전 저장                      |        |
| `revert`           | 앞선 버전으로 되돌리기 (되돌림도 새 버전) |        |

### 가. 내 컴퓨터 서버로 쓰기 (팀 서버를 올리기 전)

**터미널 1**: 서버를 켜 둬요. Claude Code를 쓰는 동안 계속 켜 둬야 해요.

```bash
pnpm mcp:serve
```

**터미널 2**: 내 Claude Code에 등록해요. 한 번만 하면 돼요.

```bash
pnpm mcp:register --local --user 부건
```

- `--user`에는 이슈 담당자와 같은 **사람 이름**을 써요. 기준을 "고친 사람"으로 남고, "바꾼 본인에게는 알리지 않기"가 이 이름으로 맞춰져요. 빼면 `git config user.name`을 써요.
- 사용자 범위(`--scope user`)로 등록돼서, 이 저장소가 아닌 다른 저장소에서 Claude Code를 켜도 `haribo`가 보여요.

### 나. 팀 서버로 쓰기 (올린 뒤)

정민님에게 받은 주소와 토큰을 `.env`에 넣어요. 토큰은 저장소나 채널에 올리지 않아요.

```
SIL_MCP_URL=https://<팀 서버 주소>/mcp
SIL_MCP_TOKEN=<팀 토큰>
```

```bash
pnpm mcp:register --user 이름
```

등록하기 전에 서버가 정상인지 먼저 볼 수도 있어요. 토큰은 `.env`의 `SIL_MCP_TOKEN`에서 읽어요.

```bash
pnpm mcp:check --url https://<팀 서버 주소>/mcp
```

저장소를 받지 않는 다른 팀은 이 한 줄이면 돼요. 이름은 헤더에 한글을 그대로 못 넣어서 퍼센트 인코딩해요 (`node -e "console.log(encodeURIComponent('부건'))"`).

```bash
claude mcp add --transport http --scope user haribo https://<팀 서버 주소>/mcp --header "Authorization: Bearer <팀 토큰>" --header "X-Sil-User: <퍼센트 인코딩한 내 이름>"
```

### 다. 써 보기

1. 아무 저장소에서 Claude Code를 **새로** 켜요.
2. `/mcp`를 입력해 `haribo`가 `connected`인지 봐요.
3. 이렇게 말해 봐요.
   - "haribo 서버 ping 해 줘" → 서버와 DB 연결, 내 이름이 나와요
   - "쿠폰 관련 기준 찾아 줘" → `search_standards`
   - "app.notify.title-length 기준 보여 줘" → `get_standard`

세션을 시작할 때 항상 적용 기준과, 내가 "관계있다"고 답한 바뀐 기준이 서버 안내문으로 함께 들어가요.

### 등록 확인·바꾸기

| 하고 싶은 일            | 명령                                    |
| ----------------------- | --------------------------------------- |
| 등록됐는지 보기         | `claude mcp get haribo`                 |
| 지우기 (다시 등록 전에) | `claude mcp remove haribo --scope user` |

`pnpm mcp:register`는 이미 `haribo`가 있으면 등록하지 않고 지우는 명령을 알려 줘요. 내 컴퓨터 서버에서 팀 서버로 옮길 때는 지운 뒤 다시 등록해요.

10/12 전에는 서버 이름이 `sil`이었어요 (D55). 예전 이름으로 등록했다면 같은 도구가 두 번 보이지 않게 `claude mcp remove sil --scope user`로 지우고 다시 등록해요.

### 주의

- `save_standard`와 `revert`는 `.env`(또는 팀 서버)가 가리키는 DB에 바로 써요. **기준은 지울 수 없어요.** 시험할 때는 읽기 도구만 쓰거나 시험용 DB를 써요.
- Claude Code를 켤 때 확인할 변경을 자동으로 보여 주는 기능(`sil brief`, SessionStart hook)과 알리기 도구(`list_pending`, `respond`)는 아직 없어요 (민수님, SIL-28·SIL-67).

## 3. CLI에서 (`sil` 명령어)

```bash
pnpm sil --help
```

명령마다 `pnpm sil <명령> --help`로 옵션을 볼 수 있어요. pnpm 없이 `node apps/cli/bin/sil.mjs <명령>`으로도 돼요.

| 명령                                     | 하는 일                                                          | DB에 쓰나요      |
| ---------------------------------------- | ---------------------------------------------------------------- | ---------------- |
| `pnpm sil doctor` (= `pnpm onboard`)     | 개발 환경, `.env`, DB, Claude Code 등록 확인                     | 아니요           |
| `pnpm sil import`                        | team-wiki/ 기준과 이슈를 DB와 비교해서 미리 보기                 | `--apply`일 때만 |
| `pnpm sil deprecate <기준ID> --reason …` | 기준 폐기 (지우지 않고 상태만 바꿈). `--replaced-by`로 대체 기준 | 예               |
| `pnpm sil changelog`                     | DB 기록으로 CHANGELOG 줄 만들기. `--append`로 파일에 없는 줄만   | 아니요 (파일만)  |
| `pnpm sil export`                        | 응답 기록 14칸 CSV + 지표("N건 중 M건")                          | 아니요 (파일만)  |
| `pnpm sil backup`                        | 표 전체를 JSON으로 `backup/`에 저장                              | 아니요 (파일만)  |
| `pnpm sil scope-check`                   | 위키 적용 범위의 코드 경로가 실제 파일과 맞는지 확인             | 아니요           |

자주 쓰는 순서:

```bash
pnpm sil import
```

```bash
pnpm sil import --apply
```

```bash
pnpm sil deprecate <기준ID> --reason "<폐기하는 이유 한 문장>" --replaced-by <대신하는 기준ID>
```

- `import`와 `deprecate`는 `.env`가 가리키는 DB에 바로 남아요. 기준은 지울 수 없으니 `import`는 미리 보기를 꼭 먼저 봐요.
- `export`와 `backup` 결과에는 DB 내용이 들어 있어서 저장소에 올리지 않아요 (`.gitignore`에 들어 있어요).
- `brief`(확인할 변경 보기)와 `status`(내 이슈와 이어진 기준 보기)는 아직 없어요 (민수님, SIL-28·SIL-29).

## 막히면

[README "막히면"](../README.md#막히면) 표를 봐요. 자주 걸리는 것:

| 증상                                                 | 해결                                                                                       |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| "TypeScript를 바로 실행할 수 없어요"                 | Node가 24.18이 아니에요. `nvm use`                                                         |
| `pnpm mcp:check`는 되는데 Claude Code에 안 보임      | `claude mcp get haribo`로 등록을 확인하고, Claude Code를 완전히 껐다 켜요                  |
| Claude Code에서 `haribo`가 `failed` (내 컴퓨터 서버) | 터미널 1의 `pnpm mcp:serve`가 켜져 있는지 봐요                                             |
| 위키 도구가 `DB_NOT_CONFIGURED`                      | 서버의 `.env`(또는 호스팅 환경 변수)에 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`가 없어요 |

팀 서버를 HTTPS로 올리는 방법은 [mcp-server README "올리기"](../apps/mcp-server/README.md#올리기-https)에 있어요.
